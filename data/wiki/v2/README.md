# V2 结构化角色资料

本目录是内容编译输入，不是直接发给浏览器的完整角色档案接口。目录名 V2 表示当前整理模型，不代表游戏客户端版本、资料实时性或所有字段均经过人工审校

## 文件

| 文件 | 用途 |
| --- | --- |
| `characters.json` | 角色身份、地区名称、游戏资料、服装、语音与原型等结构化档案 |
| `outfits.json` | 服装扁平记录，使用稳定标识连接角色 |
| `moegirl-roster.json` | 补充档案及来源，不能直接视为可育成角色集合 |
| `meta.json` | 获取批次、来源站点、版本范围及统计 |

统计以实际文件与编译报告为准。`meta.json` 的生成时点和日服范围不证明每位角色在简中或繁中服也已实装

## 名称与实体

`id` 是稳定连接键，显示名、别名及翻译不能替代主键。`names` 保存日文、英文、简繁中文及补充译名，来源或置信度字段必须保留。英文原型名不一定等于经过官方确认的角色英文名，推定值不得自动升级为 confirmed

界面按界面语言决定显示内容：简中可包含其他别名、日文原名、英文名和外号；繁中使用其他译名、日文原名和英文名，不混入简中外号；日语以日文原名和英文名为主。搜索可使用经过整理的索引，但不要将命中原因写成开发术语

`implementation`、是否有独立页面和是否属于站点分类是不同信息。编译器结合字段完整性与实体分类区分可育成、计划角色和 NPC，不将所有补充档案都送入需要唯一答案的竞赛题库

## 关系与空值

角色、服装、原型马、技能及赛事是不同实体，使用稳定 ID 与来源连接。角色级适性不能无说明复制成每套服装的真实适性，技能名字符串相似也不能当作已确认归属

缺少原型 ID、名次、育成目标或译名时保留缺口。历史比赛中已知名次的空档不重新编号，来源冲突保留依据供人工处理，不能为满足题量在编译时补造事实

## 更新与验证

资料获取与补全程序放在内部工作区。本目录只接收筛选后的构建快照，人工审校按相应台账管理，不将待审核记录批量改为通过

```bash
go run ./cmd/content build --dry-run
go run ./cmd/content build --out content
go run ./cmd/content verify
```

以上从仓库根目录执行。需要重点审查新增/移除实体、ID 变化、译名变化、字段置信度、公开私有边界与各玩法准入。模型消费者及资源发布方式见[内容流水线](../../../internal/content/README.md)，许可见[来源说明](../../../docs/第三方依赖与资料来源.md)
