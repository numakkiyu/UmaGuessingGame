# Wiki 资料快照

本目录保留内容构建需要的资料快照与来源元信息，不存放抓取程序、原始网页缓存或运行数据库。应用运行不应为完成一局而重新抓取整站资料

## 文件职责

| 文件 | 内容与使用方式 |
| --- | --- |
| `characters.json` | 基础角色快照，兼容整理流程中的已有字段 |
| `horses.json` | 原型马与赛事关联资料，按标识和来源连接 |
| `skills.json` | 技能定义、整理字段及归属依据 |
| `meta.json` | 此层快照的生成信息与统计 |
| `v2/` | 结构化角色、服装与补充档案，详见[模型说明](v2/README.md) |

生成时间记录资料采集批次。字段覆盖范围见对应 JSON 与编译器，游戏实装状态需按地区和时间核对

## 更新要求

保留来源 URL、外部标识、置信度和空值。缺失值使用 `null` 或实际模型的缺省表达，不填 0、空关系或猜测值冒充事实；推定日文名不能改成确证，planned 也不等于可以进入可育成题库

抓取结果先在内部工作区检查格式、数量差异和许可，再将经过筛选的构建输入更新到此目录。对手工修订使用 `data/manual/` 对应台账，避免下次快照覆盖有依据的纠错。资料获取工具与缓存不随公共项目发布

## 编译与验证

在仓库根目录：

```bash
go run ./cmd/content build --dry-run
make content-compile
make content-verify
```

内容编译不修改快照，将可用题目、排除理由与数据缺口写入构建报告和内容包。记录通过来源、字段与玩法条件检查后才进入题库，来源 URL 与语义审校结果分别记录

完整输入、公开与私有 section、素材处理见[内容流水线](../../internal/content/README.md)。资料来源及素材许可见[来源说明](../../docs/第三方依赖与资料来源.md)
