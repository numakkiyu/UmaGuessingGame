# 账户登录与游玩准入

> [!WARNING]
> 账户登录为实验性功能，默认关闭，暂不建议开启

配置后可使用第三方账户登录，并分别设置好友、派对和随机匹配的登录要求。普通单人挑战免登录

默认配置省略 `accounts`。项目不提供注册、密码管理或多平台账户合并

## 身份边界

| 标识 | 用途 | 生命周期 |
| --- | --- | --- |
| 账户 UUID | 已验证外部身份对应的内部账户 | 保存于数据库，跨登录保持一致 |
| 匿名游玩会话 ID | 当前浏览器的联机操作与权限 | 按原有会话规则到期、撤销 |
| 房间内六位标识 | 区分昵称相同的房间成员 | 只属于当前房间 |
| 昵称与头像 | 全站展示外观 | 保留全局个人设置，与认证身份无关 |

账户登录和匿名游玩是两条并行路径，不替换各自 ID，不按昵称、邮箱、IP 或浏览器指纹合并账户

外部身份以 `(issuer, client_id, subject)` 唯一映射到内部 UUID，OIDC 使用经过验证的 `sub`，原生 OAuth 适配读取第三方当前用户接口的稳定 ID，应用 ID 作为隔离范围，避免应用级或成对主体混用

同一外部身份对应固定账户 UUID，不同平台的账户分别管理

登录成功或退出登录前，服务端先取消尚未开局的匹配，再离开当前浏览器所在的房间，转移主持人并撤销旧实时权限。正在进行的个人对局按认输处理，团队成员退出不代表全队投降。清理失败时保留原身份，供玩家重试

昵称和头像保留，重新加入时建立新的游玩会话。已有房间记录不会自动转到另一个账户。要求登录的房间禁止同一账户同时占据两个席位或重复活跃排队；允许匿名游玩的形式继续使用匿名会话规则

## 手动启用实验性账户接入

接入需要以下配置

1. 可用的 HTTPS 域名、固定回调地址与可信反向代理
2. 在提供方申请的客户端 ID 与密钥
3. 服务端可以访问提供方的发现文档、公钥和令牌端点
4. 设置 `UMA_SECURE_COOKIES=true`、精确的 `UMA_ALLOWED_ORIGINS`，保持 `UMA_ALLOW_MISSING_ORIGIN=false`

在仓库根目录复制已有策略，保留玩法、容量和验证设置

```sh
cp config/cloud.json config/accounts.local.json
```

`config/*.local.json` 已由 Git 忽略。编辑 `config/accounts.local.json`，在现有根对象中添加下面的 `accounts` 字段，不要用这一片段覆盖整个文件。替换域名、客户端 ID 和 Microsoft 租户标识，填写需要启用的提供方

```json
{
  "accounts": {
    "enabled": true,
    "publicUrl": "https://game.example.com",
    "requireLogin": {
      "friend": false,
      "event": false,
      "matchmaking": false
    },
    "idleSeconds": 86400,
    "absoluteSeconds": 604800,
    "providers": [
      {
        "id": "microsoft",
        "enabled": true,
        "protocol": "oidc",
        "issuer": "https://login.microsoftonline.com/你的租户ID/v2.0",
        "clientId": "Microsoft 应用客户端 ID",
        "clientSecretEnv": "UMA_MICROSOFT_CLIENT_SECRET"
      },
      {
        "id": "google",
        "enabled": true,
        "protocol": "oidc",
        "issuer": "https://accounts.google.com",
        "clientId": "Google 应用客户端 ID",
        "clientSecretEnv": "UMA_GOOGLE_CLIENT_SECRET"
      }
    ]
  }
}
```

`publicUrl` 必须是实际公开访问的 HTTPS 源站地址，不包含路径、查询或用户信息，回调地址由其固定生成，不采用请求 Host 或客户端输入拼接

密钥放在 `clientSecretEnv` 指定的环境变量中，通过部署平台的私密环境设置或受保护的环境文件注入。不要将密钥写进 JSON、前端、Git 或日志，也不要直接写入会留在历史记录中的命令

直接运行 Go 前，在当前进程环境中准备两项密钥，再指定本地策略文件

```sh
UMA_SECURE_COOKIES=true \
UMA_ALLOWED_ORIGINS=https://game.example.com \
UMA_ALLOW_MISSING_ORIGIN=false \
UMA_PUBLIC_ORIGIN=https://game.example.com \
go run ./cmd/server --config config/accounts.local.json --addr 127.0.0.1:8080
```

这条命令启动 HTTP 后端，由配置好的 HTTPS 反向代理转发。公网策略需要同时配置可信代理范围，详见[配置参考](配置参考.md)。局域网启用账户登录也需要 HTTPS、安全 Cookie 和 Origin 校验

| 配置 | 效果 |
| --- | --- |
| `enabled: false` | 隐藏账户状态和登录按钮，保持原匿名游玩 |
| `enabled: true`、三个要求均为 `false` | 可选择登录，三个形式也允许匿名进入 |
| `requireLogin.friend: true` | 好友游玩必须登录 |
| `requireLogin.event: true` | 派对创建与参与必须登录 |
| `requireLogin.matchmaking: true` | 随机匹配、确认和对局必须登录 |

三个要求独立，不能用一个形式的匿名准入绕过另一形式要求，普通单人挑战始终免登录，原有玩法启用开关与账户要求取交集，登录不会开放原本关闭的玩法

账户总开关关闭时设置任一 `requireLogin: true` 会启动失败，不会静默降低为匿名访问，启用却没有配置好身份提供方、密钥缺失、来源发现失败等也会启动失败

后台对房间读取、加入、提交、管理、匹配票据、恢复以及实时连接都检查登录，受保护席位绑定账户，其他账户不能凭旧匿名 Cookie 或恢复码继承席位，已单独配对的大屏身份仅可按现有只读权限展示

### Docker 注入与停用

默认 Compose 不传入账户密钥。启用时，在部署目录创建覆盖文件，例如 `compose.accounts.local.yml`，内容如下。该文件和包含密钥的环境文件只保留在部署环境，不加入版本控制

```yaml
services:
  app:
    environment:
      UMA_CONFIG: /etc/umaguess/accounts.local.json
      UMA_PUBLIC_ORIGIN: https://game.example.com
      UMA_ALLOWED_ORIGINS: https://game.example.com
      UMA_ALLOW_MISSING_ORIGIN: "false"
      UMA_SECURE_COOKIES: "true"
      UMA_GOOGLE_CLIENT_SECRET: "${UMA_GOOGLE_CLIENT_SECRET:?set in deployment environment}"
      UMA_MICROSOFT_CLIENT_SECRET: "${UMA_MICROSOFT_CLIENT_SECRET:?set in deployment environment}"
```

默认 Compose 已将 `./config` 只读挂载到 `/etc/umaguess`，因此本地 JSON 文件无需额外挂载。通过受保护的环境文件提供变量后启动

```sh
docker compose --env-file /absolute/private/accounts.env \
  -f docker-compose.yml -f /absolute/private/compose.accounts.local.yml config --quiet
docker compose --env-file /absolute/private/accounts.env \
  -f docker-compose.yml -f /absolute/private/compose.accounts.local.yml up -d --build
```

检查时使用 `config --quiet`，完整配置输出会展开密钥。修改 JSON 或环境变量后重启服务，提供方配置在启动时读取

停用时删除私有配置中的 `accounts` 字段，或设 `enabled: false` 并将三个 `requireLogin` 一并设为 `false`，然后重启。Docker 部署也可移除专用覆盖文件，恢复原配置并重新创建容器。停用不会删除既有账户映射；如需清理数据，先备份并单独制定数据保留方案

## 登录预设

| 预设 | 支持方式 | 配置注意 |
| --- | --- | --- |
| Google | OIDC | issuer 使用 `https://accounts.google.com` |
| Microsoft | OIDC | 使用具体租户的 v2 issuer，暂不支持通过 `common` 接受任意租户 |
| GitHub | 原生 OAuth 2.0 或 OIDC 身份代理 | 原生适配调用 `/user`，使用数值 `id`，不使用可能更名的 login |
| X | 原生 OAuth 2.0 + PKCE 或 OIDC 身份代理 | 读取 `/2/users/me` 的 `data.id`，权限为 `users.read tweet.read` |
| QQ | OIDC | 通过提供 QQ 登录的 OIDC 身份服务接入 |
| Facebook | OIDC | 通过提供 Facebook 登录的 OIDC 身份服务接入 |
| 其他账户 | 标准 OIDC | 自定义 ID、可信 issuer 和三语名称 |

QQ 和 Facebook 使用身份服务的 issuer、客户端 ID 和密钥。GitHub 与 X 可直接使用平台 OAuth 2.0，也可通过 OIDC 接入

个人设置按配置顺序显示已启用的登录方式

每个提供方需要在对应平台登记如下精确回调地址

```text
https://game.example.com/api/v1/account/callback/google
https://game.example.com/api/v1/account/callback/microsoft
```

其他提供方将最后的 ID 替换为配置中的提供方 ID

## 标准接口

接口收录在 `api/openapi.json`，前端类型由同一文档生成

| 方法与路径 | 用途 | 返回 |
| --- | --- | --- |
| `GET /api/v1/config` | 查询最小公开账户配置和各玩法要求 | `accounts.enabled`、`requireLogin`、登录方式与可用性 |
| `GET /api/v1/account` | 读取当前本站账户状态 | `authenticated`，登录后包含 UUID、有效期和内存使用的 CSRF 值 |
| `POST /api/v1/account/logins/{providerId}` | 发起授权，检查 Origin | JSON `{ "returnTo": "/friends" }`，返回授权跳转地址 |
| `GET /api/v1/account/callback/{providerId}` | 消耗浏览器绑定的单次登录事务 | 303 回到允许的本站入口，只带通用登录结果 |
| `POST /api/v1/account/renew` | 延长活跃会话并按期轮换 Cookie | 需要账户 Cookie、Origin 和 `X-Account-CSRF` |
| `DELETE /api/v1/account/session` | 撤销当前浏览器的账户登录 | 需要同上三个校验，返回 204 |

`returnTo` 只允许 `/`、`/friends`、`/party`、`/matchmaking`，不接受外部跳转，账户 CSRF 与匿名游玩 CSRF 相互独立，不能互换，退出登录不删除账户映射

本站是外部授权客户端，不是 OAuth 授权服务器，不提供密码授权、客户端凭证兑换用户或代发上游访问令牌

## 安全与会话期限

- 采用授权码流程、S256 PKCE、五分钟有效且单次使用的 state，浏览器事务 Cookie 绑定提供方，OIDC 额外检查签名、issuer、audience、nonce、有效期、授权方以及存在时的访问令牌摘要
- OIDC 验证由成熟库完成，不自行解码后直接信任 JWT，签名算法仅放行 RS256、ES256
- 上游访问令牌、ID 令牌只在后端本次请求内使用，不返回前端，不保存到数据库，不申请离线刷新权限
- Cookie 为 `__Host-uma_account`，启用 Secure、HttpOnly、SameSite=Lax、Path=/，不指定 Domain，数据库只保存随机 Cookie 的 SHA-256 摘要
- 默认空闲有效期 24 小时，绝对有效期 7 天，范围分别为 5 分钟至 7 天、空闲期限至 30 天，所有续期受绝对到期约束
- 前台可见页面定期续期，按剩余有效期提前安排，后台隐藏页面不持续续期，达到绝对期限必须重新登录
- 主动续期时满 30 分钟轮换 Cookie，旧值只保留 30 秒以完成已经发出的并行请求，条件更新避免多个标签页把旧 Cookie 覆盖回来
- CSRF 仅在前端内存持有，不放 localStorage、sessionStorage、查询串或缓存，后端重启后重新读取状态即可获取新的值
- 外部身份请求只允许可信配置中的公开 HTTPS，拒绝私网、回环、元数据地址、非 443 端口、用户信息与重定向，设置连接数、超时、响应大小上限
- 登录事务数量上限 1024，每 IP 登录与回调共用每分钟 30 次、突发 10 次的限流，原有入口总并发和流量限制继续生效
- API 不缓存账户响应，回调使用 no-referrer，上游错误、授权码、state、token 与完整 Cookie 不进应用日志，反向代理也必须避免记录回调查询参数

本站退出只撤销本站会话，不代表同时退出 Google 等第三方网站，当前使用单实例 SQLite 与进程内登录事务，重启时未完成授权需重新开始，多实例部署须另行增加共享事务存储与统一调度

## 页面与文案

启用后，昵称下方原问候语位置显示“未登录／已登录”，不另加气泡。读取中或失败时显示对应状态；停用后保留原问候语，既不加载账户界面，也不请求账户接口

个人设置保留全局昵称与头像，第三方登录位于保存和取消按钮上方。点击后立即显示等待状态并阻止重复操作，失败后恢复按钮并打开橙红色角色错误弹窗，登录成功显示绿色确认状态。动画不延迟请求，尊重系统与局内减少动态设置

要求登录的入口显示清楚的参加提示，并引导打开右上角设置，登录失败复用现有橙红色角色错误弹窗，页面不输出令牌、认证端点、协议名、堆栈或上游报错

简体、港台繁体与日语采用对应语境，“账户／帳號／アカウント”“登录／登入／ログイン”保持一致，个人昵称不被第三方显示名覆盖

## 登录方式模板与按需展示

关闭的登录方式隐藏。启用的提供方配置有误时，服务拒绝启动并记录错误

`accounts.providers` 按数组顺序展示。只开启 Microsoft 和 Google 时，页面只显示这两个按钮

登录方式共用按钮样式和反馈。1 个入口单列，2 个或 4 个双列，其他数量桌面最多三列、手机最多两列

预设使用官方图标和名称。`displayNames` 可设置简中、繁中、日文名称，`iconPath` 可设置本地图标

自定义标准 OIDC 提供方可在 `providers` 数组中增加如下条目，不需要为其添加前端组件

```json
{
  "id": "club",
  "enabled": true,
  "protocol": "oidc",
  "issuer": "https://identity.example.com",
  "clientId": "运营者申请的客户端 ID",
  "clientSecretEnv": "UMA_CLUB_CLIENT_SECRET",
  "displayNames": {
    "zh-Hans": "同好会账户",
    "zh-Hant": "同好會帳號",
    "ja": "サークルアカウント"
  },
  "iconPath": "/assets/ui/providers/club.svg"
}
```

- 提供方 ID 以小写字母开头，只含小写字母、数字和短横线，长度 1 至 32，最多配置 12 个提供方，ID 不可重复
- 自定义提供方必须使用 OIDC，三个本地化名称各 1 至 48 个字符，拒绝控制字符与隐藏的文字方向控制符；预设未配置名称时使用内置名称
- `iconPath` 可省略，省略时使用统一的登录图标；配置时只允许 `/assets/ui/providers/` 下的 SVG、PNG、WebP，禁止外部 URL、data URL、路径穿越与动态脚本
- 自定义图标放入 `web/public/assets/ui/providers/` 后随前端构建发布，不将密钥、身份端点或令牌写入图标文件，记录图标来源
- 官方图标使用原比例与规定配色，图标统一 20 × 20 CSS 像素，触控按钮至少 44 像素高，支持长名称、键盘焦点与减少动态效果偏好
- 自定义回调地址仍为 `publicUrl + /api/v1/account/callback/{id}`，必须在提供方登记精确地址
- 公开配置只含提供方 ID、可用性与展示名称、图标路径，issuer、clientId、环境密钥名称以及凭证均不返回前端

自定义提供方使用标准 OIDC；原生 OAuth 2.0 适配支持 GitHub 和 X

按钮名称最多显示两行，读屏使用完整名称。图标加载失败时使用通用登录图标

## 特雷森挑战赛与训练员挑战榜

这两项为 beta 功能，已有界面组件，计分与榜单接口尚未接入，未开放游玩入口

| 功能 | 用途 | 当前状态 |
| --- | --- | --- |
| 特雷森挑战赛 | 一人独立作答，题目与成绩由服务端确认 | 默认关闭，已有界面框架 |

普通单人挑战继续免登录，保留本地出题和游玩记录。挑战榜不导入本地记录、旧匿名挑战、好友房间、随机匹配或派对成绩

计分方案以经典猜角色为起点，沿用九项提示和姓名搜索。角色选择、剩余次数、时限、得分与账户归属由服务端验证。各玩法独立计分、同分并列，设备时钟和网络延迟不参与排名

候选规则为最多猜错 8 次、每局 20 分钟。正式规则与周期将在接入计分服务时确定
