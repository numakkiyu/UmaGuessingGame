# 配置参考

配置分为部署策略 JSON、进程参数和 Compose 插值三层。Go 进程不自动读取 `.env`；直接运行时使用 shell 导出的 `UMA_*` 或命令行参数，Compose 则从 shell / `.env` 读取插值并只传入 `environment` 中声明的变量

## 优先级与文件选择

`--config` 优先于 `UMA_CONFIG` 选择 JSON 文件；对支持覆盖的字段，优先级为 JSON < 环境变量 < 显式命令行参数。未设置配置文件时使用程序默认策略。JSON 拒绝未知字段与错误类型，修改后需重启生效

示例：

```bash
UMA_SECURE_COOKIES=true \
UMA_ALLOWED_ORIGINS=https://uma.example.com \
go run ./cmd/server --config config/cloud.json --addr 127.0.0.1:8080
```

容器路径是 `/etc/umaguess/cloud.json`，不要将宿主相对路径当作容器文件路径。支持的全部参数可用 `go run ./cmd/server --help` 查询

## 常用进程变量

下表默认值指直接运行 Go，`make dev` 与 Compose 会覆盖部分目录及监听设置

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `UMA_ADDR` | `127.0.0.1:8080` | HTTP 监听地址 |
| `UMA_DATA_DIR` | `./data/runtime` | SQLite、锁与签名密钥所在目录 |
| `UMA_CONTENT_DIR` | `./content` | 带 current 指针的内容目录 |
| `UMA_WEB_DIR` | `./web/dist` | 前端文件目录配置，构建时同步嵌入产物 |
| `UMA_BACKUP_DIR` | `./backups` | backup 子命令默认输出目录 |
| `UMA_DEPLOYMENT` | `lan` 或所选 JSON 值 | `lan` / `internet` |
| `UMA_LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |
| `UMA_SECURE_COOKIES` | `false` | 公网 HTTPS 必须开启 |
| `UMA_ALLOWED_ORIGINS` | 空 | 逗号分隔的完整 Origin，空时按请求 Host 校验 |
| `UMA_TRUST_PROXY` | `false` 或 JSON 值 | 是否信任限定代理的转发头 |
| `UMA_TRUSTED_PROXY_CIDRS` | 空或 JSON 值 | 可信代理 CIDR，开启代理信任时必填 |
| `UMA_ALLOW_MISSING_ORIGIN` | `false` | 受控私网非浏览器写入例外 |
| `UMA_METRICS_LOCAL_ONLY` | `true` | 指标限制到回环连接 |
| `UMA_SESSION_TTL` | `168h` | 匿名会话期限 |
| `UMA_DISPLAY_TTL` | `12h` | 展示会话期限 |
| `UMA_BUSY_TIMEOUT` | `1s` | SQLite 忙等待，使用 Go duration，不是 `_MS` 变量 |
| `UMA_SYNCHRONOUS` | `FULL` | SQLite 持久性策略 |
| `UMA_READ_CONNS` | `8` | 读连接池大小 |
| `UMA_QUEUE_CAPACITY` | `128` | 每房间命令队列上限 |
| `UMA_SHUTDOWN_GRACE` | `15s` | 应用优雅关闭等待 |

不要将 `0.0.0.0/0` 或 `::/0` 作为可信代理范围。容器中看到的代理地址与宿主可能不同，应按实际连接来源配置。`UMA_PUBLIC_ORIGIN` 是启动辅助使用的公开地址；仍应明确设置 `UMA_ALLOWED_ORIGINS`，尤其是不同端口、Vite 或反向代理场景

## 玩法开关

[lan.json](https://github.com/numakkiyu/UmaGuessingGame/blob/main/config/lan.json)适合受控局域网活动，[cloud.json](https://github.com/numakkiyu/UmaGuessingGame/blob/main/config/cloud.json)提供较保守的公网示例

`forms` 包含 `local`、`verified`、`solo`、`friend`、`matchmaking`、`event`，分别控制单人挑战、计分挑战、单人房间、好友房间、匹配及活动入口。`modes` 可按玩法进一步限制某种形式；任意层关闭，入口即受限，同时仍需满足该玩法人数与内容条件

云端示例关闭匹配与活动，并对部分高交互玩法进一步限制，部署者可按演练结果调整。关闭入口不应用于清除已开始对局或已确认回执；不要删除玩法引擎来实现配置开关

## 容量与排队

| limits 字段 | LAN 示例 | Cloud 示例 | 作用 |
| --- | --- | --- | --- |
| `connections` | 2000 | 300 | 实时连接总数 |
| `connectionsPerRoom` | 220 | 32 | 房间连接数 |
| `connectionsPerSession` | 2 | 2 | 单会话连接数 |
| `playersPerRoom` | 100 | 16 | 房间人数上限，玩法可能另有更低限制 |
| `spectatorsPerRoom` | 100 | 12 | 观众上限 |
| `queuedCommands` | 4096 | 512 | 全局处理中及等待的命令数 |
| `rateLimitBuckets` | 20000 | 10000 | 限流键内存上限 |
| `verifiedChallenges` | 512 | 128 | 进行中的计分挑战数量 |
| `sessionCreatePerIPMinute` | 600 | 120 | 同出口 IP 每分钟会话创建限制 |
| `sessionCreatePerIPBurst` | 200 | 30 | 同出口突发容量 |

这是保护阈值，不是并发性能证明。同一活动可能共享出口 IP，不能将 IP 数当作人数。优先控制连接、命令与会话行为，配合实际活动规模调整，避免误伤共享网络

## 可选 Turnstile

在配置 JSON 的 `turnstile` 中设置：

- `enabled`：默认 `false`
- `siteKey`：可公开的站点键
- `secretEnv`：服务端读取的环境变量名，默认 `UMA_TURNSTILE_SECRET`
- `hostnames`：允许的主机名，不含协议和端口
- `operations`：需要入场验证的操作，如建房、入房、创建活动和挑战
- `grantSeconds`、`maxConcurrent`：验证授权期限及并发验证限制
- `browserSignals`、`signalPerMinute`、`signalBurst`：可选浏览器辅助信号及限额

将 secret 留在部署环境，不能写入公开 JSON 或前端。默认 Compose 已透传 `UMA_TURNSTILE_SECRET`；若自定义 `secretEnv`，也必须补充对应环境透传。验证开启时应嵌入游戏准备界面，并有失败重试和可访问提示，不能只放一个无上下文验证框

## Compose 专用设置

`UMA_HOST_PORT` 控制宿主端口，默认 8080；容器内固定监听 `:8080`。默认 Origin 跟随本机端口，但远程访问必须同时指定公开地址和允许 Origin

`UMA_RUNTIME_IMAGE`、`UMA_BUILD_GO_PROXY` 是构建选择。默认使用 distroless 非 root 运行镜像，受网络限制时可以显式选择 Dockerfile 支持的替代镜像与 Go 代理，不能随意使用未知来源镜像

Compose 的 30 秒 `stop_grace_period` 大于应用默认 15 秒关闭等待。若通过覆盖文件传入更多 `UMA_*`，确认容器路径、挂载与关闭预算一致，再用 `docker compose config --quiet` 检查；不要将包含实际密钥的完整配置输出贴到公开 Issue

## 随机匹配

`matchmaking` 与 `forms.matchmaking` 分开控制：前者管理大厅及排队资源，后者决定是否允许新玩家排队。关闭大厅不会取消已开始的比赛，也不会阻止原票据恢复、确认或离开

```json
{
  "matchmaking": {
    "lobbyEnabled": true,
    "queueCapacity": 1000,
    "proofBits": 16
  }
}
```

| 字段 | 默认值 | 范围与含义 |
| --- | --- | --- |
| `lobbyEnabled` | `true` | 是否开放大厅和公开汇总，关闭时对应入口隐藏；不删除玩法 |
| `queueCapacity` | `1000` | 等待和确认中的总人数，`0` 使用默认，最大 `10000` |
| `proofBits` | `16` | SHA-256 前导零位数，`0` 使用默认，可设置 `12`–`20`；不存在关闭工作量验证的选项 |

公开队列使用固定赛制：经典猜谜双人、经典猜谜四人、档案排序四人、记忆翻牌四人。每个队列同时受玩法开关、内容准入、单房人数上限约束。`modes.<modeId>.matchmaking` 可以分别关闭某项玩法的公开队列。公网示例默认关闭匹配与大厅，局域网示例默认开启

Turnstile 仍由 `turnstile.enabled` 和 `turnstile.operations` 控制。将 `createMatchmakingTicket` 纳入验证范围后，发放工作量挑战前同样检查入场授权；关闭 Turnstile 也必须完成工作量挑战。挑战绑定当前匿名会话和赛制，90 秒有效、一次消费；新挑战会替换同会话的旧挑战，避免无限堆积

浏览器在独立 Worker 中计算，后台只验算一次摘要。哈希不是“唯一真人”证明，也不是浏览器指纹，不保证阻止有算力的机器人；匿名 Cookie、服务端限流、单会话单场、确认期限、心跳租约和容量上限共同提供约束。IP 仅用于宽松的共享出口流量保护，不用作玩家身份

排队窗口为 120 秒，配齐后全员在 20 秒内确认，页面每 3 秒续约一次 35 秒的在场租约。心跳不会延长确认期限。关页或长时间后台停留会退出等待；拒绝、取消或过期会释放同组其他玩家，其他人保持原排队顺序，但下一场仍要重新确认。取消或错过确认有 15 秒冷却

大厅每 5 秒读取一次汇总，后台缓存最多 2 秒。汇总只包含各赛制排队人数、确认人数、正在进行的比赛参与人数和比赛房间数，不返回玩家标识、昵称或挑战结果。比赛人数指进行中对局的未离场参赛者，不代表实时 WebSocket 在线人数

### 随机匹配的空闲回收

`matchmaking.idleEnabled` 默认 `true`，只用于随机匹配；`matchmaking.idleSeconds` 默认 `60`，可设为 `15` 至 `300` 秒，`0` 表示采用默认值。好友房和派对不受此设置影响

计时从开放作答开始，翻牌的记忆预览不计入。全场没有有效提交才取消，不计成绩或胜负，并释放排队占位；取消后需等候 15 秒才能再次排队。任意一人有效提交后，本局按原定时限继续。心跳、刷新、移动未提交的排序草稿、被拒绝的操作不会保住空闲对局

该规则回收整场无人作答的房间，不声称能识别全部机器人。一次有效作答也可能来自自动化；须结合单会话限制、可选入场验证、强制工作量挑战、请求限流和队列容量控制

## 网络容量与安全预算

`limits.apiRequests` 限制同时处理的普通请求数，`limits.requestPerIPMinute` 与 `limits.requestPerIPBurst` 在查找会话前限制单一来源的请求速率。该限制用于防止无效凭证洪泛；共享网络中的正常玩家仍由会话级额度区分

`limits.connections`、`connectionsPerRoom`、`connectionsPerSession` 限制实时连接，实时握手还使用独立的短时并发槽位。SSE 和 WebSocket 的心跳、帧大小、慢写入处理由实时配置负责。公网部署必须在 HTTPS 终止层启用 WSS、设置 Secure Cookie，并配置可信的 `AllowedOrigins`

这些数字是单进程保护线，不代表公网抗攻击容量。面向公开活动时，应在应用前配置 CDN、反向代理或 WAF 的连接建立速率、请求体大小和洪泛清洗

## 入场确认与异常流量

`turnstile.enabled` 是总开关。示例配置继续保持关闭；开启前需要填写真实的 `siteKey`、允许的 `hostnames`，并在部署环境提供 `secretEnv` 指定的密钥。关闭时不加载 Cloudflare 脚本、不显示确认卡，也不保留验证占位或全屏动画。修改配置后重启生效

| 配置项 | 默认值 | 范围与作用 |
| --- | --- | --- |
| `adaptive` | `true` | 只在总开关开启时生效，根据已认证会话连续触发自身限流的情况要求重新确认 |
| `riskThreshold` | `6` | `3..100`，一个时间窗口内被会话自身操作限流拒绝的次数 |
| `riskWindowSeconds` | `60` | `10..600`，累计拒绝次数的时间窗口 |
| `grantSeconds` | `900` | `60..3600`，一次确认的有效时间，上限同时受匿名会话到期时间约束 |
| `operations` | 建房、入房、排队、创建挑战、创建活动 | 需要普通入场确认的操作；与异常确认独立 |

普通入场展示浅色主题确认卡。异常流量展示全屏暗幕和红色边缘流光，卡片仍保留完整可读的 Cloudflare 控件。后端确认通过后显示短暂成功状态、恢复页面亮度并褪去红色提醒。三种语言为简体中文、港台繁体中文与日文；手机使用紧凑控件，宽屏使用伸缩控件。切换尺寸档位会重新准备控件；单纯切换语言不会丢弃正在完成的挑战或重复提交

异常累计只使用通过会话鉴权后的自身限流结果。共享 IP、房间公共额度耗尽、插件、开发者工具、浏览器指纹均不直接触发此判断。确认成功清除累计次数并签发绑定当前会话的 HttpOnly 短时凭据；正常有效期内不会重复确认，新一轮异常可撤销旧凭据。限流额度不会因确认成功而重置，避免验证成为绕过限流的入口

页面初次打开会读取当前状态，启用自适应检查时，前台页面每分钟最多检查一次，切回页面或恢复联网也受至少 45 秒的间隔约束。该检查不创建匿名身份。取消全屏确认后，当前页面的后台检查不会反复打断；继续执行受保护操作时仍须确认。普通业务额度耗尽时，身份读取与 CSRF 恢复、确认状态读取、验证提交仍各有受限的恢复路径

该机制保护应用内已识别会话，不能替代匿名入口限流、HTTPS、反向代理容量保护或 CDN/WAF。尚未建立会话的洪泛与静态页面/CDN 流量由入口及部署层处理，不能把同出口的所有玩家一起送进验证码。风险记录和令牌占用记录均有数量与有效期上限，保存在当前服务进程内；服务重启会令旧签名通行凭据失效

参考：[Cloudflare 服务端验证](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)、[控件配置](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/widget-configurations/)、[公开测试键](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)

### 验证控件外观的可调整范围

当前产品使用官方浅色主题与 `appearance: "always"`，外层卡片、角色插图、留白和状态提示由项目样式统一；不对第三方内部 DOM 注入 CSS。强制设置父页面后代样式不能可靠改变内部的文字、勾选框或品牌区域，不能靠裁切、遮罩、代理改写脚本作为主题适配方案

Cloudflare 官方支持 `interaction-only`：只有需要人工交互时才展示控件。它可以作为后续减少原生组件视觉干扰的方案，但应同时实现主题化准备状态、人工交互展开、错误与超时处理，避免留下空验证卡。当前产品尚未采用该方案，仍使用 `appearance: "always"`

若确实需要去除提供方品牌，可查看官方 [Offlabel](https://developers.cloudflare.com/turnstile/additional-configuration/offlabel/)。该功能需要符合相应 Enterprise 授权并由 Cloudflare 管理端启用；不是项目配置中的免费去标识开关，仍需要展示要求的隐私信息

### 验证恢复的尺寸与退出边界

控件尚未完成时，切换紧凑与伸缩尺寸档位会重新准备控件。已经完成验证、正在提交或尚未收到提交结果时保留原结果，避免旋转手机或调整窗口造成重复验证；需要重新确认时按当前尺寸挂载控件

关闭确认、离开页面或再次打开确认后，旧的身份恢复和浏览器特征计算不得继续发出验证请求或覆盖新面板。第三方脚本加载失败、控件不受支持，以及挂载后 45 秒既无结果也未进入交互挑战时，保留主题错误提示、重试和返回入口；进入人工交互挑战后不使用该 45 秒准备超时中断玩家操作

## 实验性账户接入

账户登录为实验性功能，默认关闭。默认配置省略 `accounts`，启用方法见下方文档

启用时，复制策略为已忽略的 `config/accounts.local.json`，手动添加 `accounts`，设置 HTTPS、Origin、安全 Cookie 及提供方密钥，再重启服务。直接运行、Docker 密钥注入、回调登记和停用步骤见[账户登录与游玩准入](账户登录与游玩准入.md#手动启用实验性账户接入)

`accounts.requireLogin.friend/event/matchmaking` 分别要求好友、派对、随机匹配登录，三项互不替代，普通单人始终免登录。总开关关闭却要求登录、启用的提供方缺少密钥等错误会阻止启动

`accounts.providers` 按数组顺序展示已启用的提供方，停用项完全隐藏。内置品牌使用官方图标，自定义 OIDC 提供方可配置三语 `displayNames` 和受限的本地 `iconPath`，无需新增前端页面。具体字段限制见[登录方式模板](账户登录与游玩准入.md#登录方式模板与按需展示)

## 单人挑战与挑战榜 beta

计分服务和榜单接口的接入要求见[挑战赛与挑战榜规划](账户登录与游玩准入.md#特雷森挑战赛与训练员挑战榜)
