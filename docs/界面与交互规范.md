# 界面、布局与交互

V2 延续赛马娘主题的明亮学园风格，参考官方与 BWIKI 的配色和内容阅读习惯。视觉参考不等于复制官网布局或获得素材许可；游戏的信息密度、操作和设备适配仍按自身任务设计

## 信息层级

页面先呈现当前任务和主要操作，再显示必要的状态、辅助信息与细则。每个操作区应有清楚的主动作，次要按钮降低强调，危险动作集中在独立区域并进行适当确认

不要用巨大连接提示条、重复规则或冗长免责声明把答题区域挤下去。等待、已提交、暂停、揭晓与结算必须有实际可辨认的状态，不能只靠按钮颜色变化表达

## 按设备选择布局

| 场景 | 推荐布局 | 检查重点 |
| --- | --- | --- |
| 手机竖屏 | 卡片、单列、局部步骤与底部操作 | 软键盘不遮按钮，长名称换行，操作不依赖悬停 |
| 手机横屏或矮窗口 | 紧凑头部，必要时两栏 | 主控不占半屏，内容可到达，不固定过高面板 |
| 平板 | 依据宽度采用表格或主辅分栏 | 触摸目标足够大，不因“像桌面”要求鼠标 |
| 普通桌面 | 对比数据用表格，任务与操作分区 | 关键列易比较，页面宽度受控，规则就近可读 |
| 大屏与投影 | 只读舞台、成绩表与分阶段展示 | 远距离字号、留白、队伍识别与秘密信息保护 |

表格转手机卡片时保持字段含义、顺序、状态与操作一致，不遗漏重要列。只有确实需要二维比较的区域使用局部横向滚动，并给出可感知提示，不用全局 `overflow-x: hidden` 隐藏布局错误

容器允许收缩，长译名、URL 和名字不会撑破页面；底部固定或 sticky 操作给内容预留高度及安全区域。页面保持自然阅读顺序，不能用 CSS 重排造成键盘与视觉顺序不一致

## 组件与弹层

按钮、选择器、下拉菜单、对话框、提示与表单校验使用项目组件和统一设计令牌。网页业务交互不调用 `alert`、`confirm`、`prompt`，不使用原生表单气泡或未经装饰的 select 作为最终界面

弹层使用可访问的焦点管理，打开后焦点进入内容，关闭后回到触发按钮，Escape 和取消行为一致。Portal 容器避免被父级 transform 或裁切困住，遮罩、内容、下拉与 tooltip 的层级不靠不断增大 z-index 修补

网页不能替换浏览器安全、权限、下载或系统界面，只控制项目自身交互。需要浏览器权限时先说明用途并由用户主动触发，不伪装系统权限对话框

## 颜色与可访问性

颜色、字号、间距、层级和动效集中到 `web/src/styles/tokens.css`。强调色、动作色与正确/接近/错误状态色分工明确，装饰粉色不冒充答题判定

结果同时有文字或符号，不只区分红绿。正文与控件检查实际前景、背景对比度，透明遮罩和背景图按真实合成效果判断，不能只计算令牌的独立色值

触摸主操作至少有足够点击区域，键盘焦点可见，图像有正确替代文本，装饰图不打扰读屏。首个关键图片、牌面准备与骨架屏尺寸稳定，避免按钮和行高因资源加载跳动

## 动画与素材

动画解释操作结果：选中、翻牌、揭晓、位置变化与成绩更新应有短而清楚的反馈。优先变换和透明度，不每帧反复改布局，不用持续闪烁吸引注意

动效使用统一时间与缓动令牌，尊重系统及局内“减少动态”。减少动态后直接显示可理解终态，不隐藏必要信息；倒计时、裁决和资源准备不由动画播放结束决定

背景放在内容外围，手机可退回渐变；动态图与视频需要实际资源、性能预算和回退方案，不能将静态插画宣传成动态素材。图片失败沿受控候选回退，不逐张弹出错误，也不使面板尺寸塌陷

## 验证

使用真实题目和真实房间审查，不拿空白占位页代替游戏画面。至少覆盖窄屏、横屏、平板、桌面和大屏，检查头部、棋盘、列表、弹层、下拉、结算及失败状态

截图复核层级、裁切与文案密度，浏览器测量核对溢出、触摸区域及焦点；两者都不能代替真实触摸、投影和弱网演练。命令入口见[测试说明](测试与质量检查.md)，文字与地区规范见[本地化与玩家文案](本地化与玩家文案.md)
