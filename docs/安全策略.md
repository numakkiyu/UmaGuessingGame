# 安全策略

本仓库当前维护 V2 重构代码。旧架构是否适用于某个线上部署，应由该部署的维护者另行确认；仓库中的代码、测试或配置上限不构成安全审计与容量认证

## 报告漏洞

请优先使用 GitHub 仓库的 **Security → Report a vulnerability** 私下报告。若该入口未启用，可在 Issue 中只请求维护者提供私密联系渠道，不要公开漏洞细节、可用凭据或他人的个人信息。项目未承诺固定响应时限

报告建议包含受影响提交、部署方式、必要配置、最小复现步骤、影响范围及脱敏日志。不要为证明问题扫描第三方实例、占满连接、影响正在举行的活动或下载他人的私有数据

## 部署安全边界

- 公网使用 HTTPS 与 Secure Cookie，准确设置玩家访问的 Origin
- 仅对实际代理开启转发头信任，明确配置可信 CIDR，不能信任任意来源的 `X-Forwarded-For`
- SQLite 运行目录由一个服务进程拥有，使用本地文件系统；不要共享实时数据库文件或横向扩容同一卷
- 数据目录、备份、签名密钥和 `.env` 不得被静态服务或 Git 公开
- `/metrics` 默认只允许回环来源；反向代理仍需显式禁止外部访问，代理连接来自回环不能替代访问控制
- 保留 HTTP 限流、连接上限、队列上限及请求大小约束，按实测调整，不能全部关闭
- 部署使用非 root 容器和持久数据卷，更新前先验证备份恢复

## 匿名身份与反滥用

会话 Cookie 是匿名身份凭据。昵称、房间分享码及房间中的六位编号都不是认证凭据；同名玩家以房间编号区分。清除 Cookie、换浏览器或隐私模式可能产生新身份，不能据此承诺唯一自然人

IP、浏览器信号和可选 Cloudflare Turnstile 用于限制机器人与滥用，不能代替会话认证、权限检查或服务端规则裁决。信号收集应最小化，不记录完整指纹明文或在日志中输出 Cookie、CSRF、验证码与签名密钥

Turnstile 在部署 JSON 中默认关闭，开启后必须在服务端验证令牌并核对主机名及操作；私密密钥不能进入前端配置。配置方法见[配置参考](配置参考.md)

## 成绩可信度

普通单人挑战由浏览器处理，其记录不作为可信比赛成绩。计分挑战和联机对局使用服务端认可的题目、提交版本及裁决结果，不能把“答案加密”或“题目带签名”解释成完全防作弊

`verified-keys.json` 保存在运行数据目录，须与数据库一起保护和备份。轮换前停服并保留旧密钥，新增随机 32 字节密钥（Base64URL 无填充）后切换 `active`，最多保留 8 个。旧密钥至少保留到最后一张相关凭据到期后再过 24 小时，并确认无需旧回执后再移除；不得在密钥损坏时覆盖生成新文件掩盖故障

## 依赖与更新

依赖版本和锁文件是审计起点。CI 包含 Go 漏洞扫描，部署者仍需跟进 Go、基础镜像和前端依赖的安全公告；一次检查通过不能证明以后不存在漏洞。更新依赖需验证构建、测试、许可证与部署兼容性，不能仅替换版本号

备份、回滚和故障处理见[维护与更新指南](维护与更新指南.md)

## V2 浏览器与服务端的信任边界

单人挑战保留离线游玩、刷新续玩和存档功能。浏览器所有者能够读取运行时答案、修改 IndexedDB、重写脚本或伪造本地完成记录；存档校验和用于检查损坏，不能认证成绩。前端混淆、前端持有的密钥、设备时间与客户端签名均不能解决这一问题。本地记录不能作为联机提交或正式比赛成绩导入

联机题目和裁决由服务端独立生成与保存。客户端只提交玩法动作，不能指定自己的得分、获胜状态、计分身份或有效提交时间。操作在写事务内重新核对成员、会话、角色、队伍及控制权，不能只相信请求进入队列前的权限快照。公开角色知识仍可能被自动解题工具使用，记忆类玩法的展示内容也可能被录制；服务端裁决不等于完全阻断辅助工具

实时连接校验完整的房间、成员、会话与角色绑定，注册后立即复核，并默认每 30 秒复核一次。退出会话会主动断开已有连接；兑换恢复码通过事务后的通知撤销原设备在该席位上的连接。普通角色变化或会话到期仍可能在下次复核时才断开，连接仅提供变更通知，敏感快照与动作继续单独授权。数据库临时读取失败不被当作确定的作弊或撤权证据

CSP、Origin、CSRF、HttpOnly Cookie 与请求限额分别用于减少网页注入、跨站操作、凭据暴露和滥用。它们不能阻止拥有浏览器控制权的人或获授权扩展修改自己的页面。不因 F12、扩展、窗口大小或可疑指纹自动判负；公网传输仍需 HTTPS/WSS，应用层签名不能替代 TLS。连接洪泛和分布式攻击还需反向代理、CDN 与部署层防护

参考：[OWASP WebSocket 安全](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html)、[OWASP HTML5 安全](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)、[MDN 扩展内容脚本](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Content_scripts)

## 可选入场确认的边界

启用 Turnstile 后，普通入场与异常流量确认共享服务端 Siteverify 校验和短时签名凭据。异常判断只累计已认证会话自身的业务限流拒绝，不将 IP、浏览器特征、扩展或开发者工具视作真人身份或作弊证据，不因验证失败自动判负

令牌摘要占用与消费记录绑定原会话，限制并发复用、跨会话复用及提供方传播期间的重复消费。未知提供方结果保留原会话的重试归属，使用稳定的提供方幂等凭据；原始令牌和密钥不写入日志、公开配置或前端资源。验证记录和风险记录设有容量及过期边界，不能无限增长

异常可撤销旧签名通行凭据；确认成功不清空请求限流桶。身份/CSRF 恢复与验证状态有独立受限通路，避免业务限流阻断人工恢复。关闭 Turnstile 时不运行这套自适应确认流程；原有鉴权、Origin/CSRF、连接容量、工作量验证和请求限流继续生效

应用内确认不能证明“一人一身份”，也不能阻止拥有有效浏览器控制权的人自动操作。匿名建会话洪泛、静态资源攻击和分布式流量仍需部署层保护。公开服务使用对应域名的站点键与密钥，测试键仅供开发使用

### 验证期间的退出与恢复

异常确认不会阻止取消本人匹配、拒绝已分配的对局、退出本人房间席位或认输。这些操作仍须通过会话认证、Origin/CSRF、幂等约束、请求限流及资源归属检查；同一接口中的接受匹配和移除其他成员仍受异常确认约束。队列保活不属于退出操作，异常状态下仍受验证约束，避免未经确认持续占用队列

清除风险状态与签署对应版本的通行凭据在同一临界区完成；检查凭据时也拒绝仍需确认的状态。新发生的异常会使之前签发的凭据失效

## 实验性账户接入

账户接入为实验性功能，默认关闭。启用时配置 HTTPS、固定回调和后端环境变量；上游令牌仅在本次后端请求中使用，本站账户 Cookie 与匿名游玩凭据分开管理

账户接入、会话期限和联机访问设置见[账户登录与游玩准入](账户登录与游玩准入.md)
