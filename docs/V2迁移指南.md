# 迁移到 V2

V2 将旧版 Next.js API、PostgreSQL / Drizzle 与 Redis 相关部署替换为 React 静态前端、Go 服务和 SQLite。它不是更换启动命令即可复用旧数据库的就地升级

## 先确定需要保留什么

| 数据或资源 | 处理方式 |
| --- | --- |
| 角色与题库资料 | 转为当前 `data/` 输入，保留来源、未知值和审校状态，再编译验证 |
| 已有 PostgreSQL 数据 | 先独立备份；当前不承诺自动导入旧会话、房间或成绩 |
| 旧会话与进行中的房间 | 不假定与 V2 凭据及状态机兼容，安排维护窗口结束旧局 |
| 图片和声音 | 逐项核对许可、来源、内容摘要与受控路径，不复制整套临时下载缓存 |
| 域名与 HTTPS | 可保留，需重设后端地址、实时转发、Origin 与 Cookie |
| 运维脚本 | 使用当前 Make / Compose 入口，旧 PM2、Next.js 或 dev compose 包装器不继续使用 |

## 建议切换流程

1. 备份旧代码版本、数据库、资源与配置，确认备份可以恢复
2. 使用独立运行目录或独立容器卷搭建 V2，不能指向旧数据库目录
3. 编译并校验内容，检查每种需要开放的玩法与数据缺口
4. 用真实玩家设备验证单人、邀请码多人及活动团队流程，核对三语与布局
5. 设置域名、HTTPS、Origin、入场验证和容量阈值，在受控窗口切换流量
6. 保留旧环境的只读备份与回退能力，确认稳定后再决定清理范围

构建步骤见[快速开始](快速开始.md)。若确需迁移旧成绩，应另行设计显式的字段映射、身份关联、去重与审计工具，先在脱敏副本演练，不把旧昵称直接认定为同一个人

## V2 内部更新

V2 内部也有数据库迁移、内容包版本与规则版本。版本字符串相同不代表数据布局没有变化；更新前记录提交与备份，已应用的迁移文件保持不可变。无法证明向后兼容时，回滚使用迁移前备份，而不是尝试让旧程序读取新数据库

运行镜像仅依赖应用、受控内容包和部署配置。维护与恢复见[维护指南](维护与更新指南.md)
