# 题库与内容编译

角色资料、赛事关系与素材在构建阶段整理成内容包。运行游戏只读取已经生成的包，无需实时抓取百科页面

## 目录

| 目录 | 内容 |
| --- | --- |
| `data/wiki/` | 角色、技能、原型与公开资料快照 |
| `data/manual/` | 字段修订、规则输入与审校台账 |
| `data/assets/` | 具有来源记录的图片与音频 |
| `content/pack-*` | 编译后的内容包，不加入 Git |
| `content/current` | 当前内容版本指针 |

## 构建

在仓库根目录运行

```bash
go run ./cmd/content build --root . --dry-run
go run ./cmd/content build --root . --out content
go run ./cmd/content verify
go run ./cmd/content current
go run ./cmd/content sections
```

`build --evidence <path>` 可输出构建报告。`verify --dir` 指向具体包目录；省略时读取当前包，其他内容根使用 `--out`

内容先写入临时目录，完整后更新 `current`。已发布包保持只读，需要修改资料时生成新包

## 公开与私有数据

`public/` 包含可提供给浏览器的角色信息、单人题目和图片；`private/` 保存联机答案、布局和仅供判题的数据。应用按权限提供文件，不直接公开整个包目录

普通单人挑战在浏览器作答，联机题目和成绩由服务端确认。二者使用不同的可信边界，详见[技术架构](技术架构说明.md)

## 题目范围

每个玩法独立检查角色实体、必要字段、素材、关系和审校状态

- 经典题的答案必须能通过比较线索区分，可猜角色与答案范围分别维护
- 九宫格需要九位不同角色能完整覆盖本局九格
- 排序字段必须有足够有效资料，同值允许并列，日期使用明确的地区口径
- 血统、赛事、路线、配对和拼图答案必须出现在本局候选中
- 语音需要有效资源及语义审校，缺少记录的内容不开放

具体规则实现与命令参数见[内容模块说明](https://github.com/numakkiyu/UmaGuessingGame/blob/main/internal/content/README.md)

## 更新资料

修正资料时记录角色、字段、原值、新值和来源 URL。音频以字节摘要绑定审校记录，图片保留来源与许可说明。编译产物不代替原始来源记录
