# 测试与质量检查

本页列出可重复使用的检查入口，不把某次历史运行结果写成当前版本的永久保证。报告结果时说明提交、环境、命令、通过项与未覆盖项，不能只说“全部完成”

## 准备

```bash
make web-install
make web-build
make embed-spa
make embed-spa-check
make content-compile
make content-verify
```

前端与隔离工具链都要安装。内容相关测试可能读取编译包，缺少包时某些测试会跳过；跳过不代表验证成功，集成验证前必须准备真实题包

## 按范围执行

| 范围 | 命令 | 主要关注 |
| --- | --- | --- |
| 提交范围 | `pnpm run repo:check` | 暂存区和已跟踪文件不含编译产物、私人数据、密钥或超大文件 |
| Go 格式与静态分析 | `make fmt-check`、`make vet` | 格式、无效用法、危险错误处理 |
| Go 测试 | `make test`、`make test-race` | 规则、事务、授权及并发行为 |
| 真实装配 | `go test ./internal/e2e/... -count=1` | HTTP、真实 SQLite、规则和内容组合 |
| 前端类型 | `make web-typecheck` | 契约调用与组件类型 |
| 前端静态检查 | `make web-lint` | ESLint 与自定义类名引用 |
| 玩家文案 | `make web-copy-check` | 内部词汇、执行位置与不合适提示 |
| 前端测试 | `make web-test` | 交互、练习规则、存储、恢复和脚本测试 |
| 构建与预算 | `make web-build`、`make web-size` | 构建成功及首屏/分块体积 |
| 页面嵌入 | `make embed-spa-check` | Go 打包页面与当前构建一致 |
| 内容 | `make content-verify` | 清单、校验和、资源与公开私有分离 |
| 契约 | `pnpm --dir web run api:check` | 生成类型没有漂移 |
| 路由 | `go run ./cmd/content contract --spec api/openapi.json --routes` | HTTP 实现与契约双向一致 |
| 容器配置 | `docker compose config --quiet` | 插值、结构与基础配置解析 |

完整本地入口是 `make check`，`make ci` 额外检查契约。`make check` 会重新构建 web，但不会自行在最终比对前复制新产物；修改页面后应先构建并 `make embed-spa`，确保嵌入检查有正确基线

[CI](../.github/workflows/ci.yml)还包含 Go 漏洞扫描与容器构建。解析 Compose 成功不等于镜像启动成功；构建成功也不等于所有玩法能完成

前端编译副本不入库，Go 的嵌入页面测试需要先执行本页准备步骤。CI 的 Go 检查下载同一次工作流中前端任务生成的产物，不从 Git 读取预编译页面。版本管理范围和正式素材准入见[贡献指南](../CONTRIBUTING.md)

## 浏览器与真实联机

`web/scripts/` 保留按功能维护的可重复回归工具。使用前阅读脚本支持的环境变量、地址与测试数据要求，运行在隔离实例，不默认复用正在进行活动的房间。有些历史脚本依赖特定准备数据，不能仅因脚本文件存在就列为当前全量通过

布局入口：

```bash
pnpm run audit:layout
```

该工具需要 Playwright 浏览器与可访问的测试服务。检查截图内容确实是目标页面，不是 403、占位页或旧缓存，截图时间与浏览器状态应可追溯

## 必须覆盖的行为

- 单人：准备资料、开始、提交、刷新、断网续玩、记录导入导出与保存失败
- 多人：创建、邀请码加入、同名区分、准备、开始、动作、超时、结算及再来一局
- 团队：成员与队伍控制、主持权转移、主持人离开、只读大屏及赛程衔接
- 网络：迟到通知、重复命令、阶段冲突、SSE 失败、退避、游标失效与恢复
- 安全：越权读取、未公开答案、并发成交、过期凭据、限流与连接释放
- UI：320px 起的窄屏、手机横屏、平板、桌面与投影，软键盘、弹层层级及焦点恢复
- 文案：简繁日的地区表达、角色名顺序、读屏文本及错误后的下一步

## 性能与人工复核

容量验证记录硬件、磁盘、网络、人数、观众、房间、玩法分布、持续时间、错误率与延迟分位数。不能用单一空闲连接数或某次本机结果证明所有云服务器都能承受相同规模

题目事实、语音语义、地区译名、趣味性和玩法平衡需要人工审校，自动检查不能取代。动画、触摸、投影和母语文案同样需要真实设备与玩家复核；未执行时应明确写未验证
