# 维护与更新指南

本文档面向项目维护者，说明日常维护时应该优先关注什么、改动后需要同步哪些内容，以及仓库文档分别负责什么。

## 一、优先维护顺序

### 1. 运行安全

优先确认：

- Turnstile 是否按预期工作
- Redis 限流是否正常
- 房间身份与只读分享是否没有越权
- 对局进行中是否不会泄露答案

### 2. 数据完整性

优先确认：

- `question_bank_ready.json` 是否非空
- 搜索索引是否与正式题库一致
- 手工补充数据是否已同步
- 题库脚本重建后数量是否符合预期

### 3. 部署可用性

优先确认：

- `.env.example` 是否完整
- Docker 启动链路是否仍然可用
- 数据库初始化是否闭合
- README 与部署文档是否仍然准确

## 二、什么时候必须更新文档

以下情况发生时，应同步修改 README 或 `docs/`：

- 新增或移除玩法字段
- 调整题库准入规则
- 修改部署方式
- 新增环境变量
- 修改图片来源和缓存策略
- 新增多人 / 好友对战的重要流程
- 修改贡献流程、Issue 模板或 CI 行为

## 三、数据维护建议

### 正式数据目录

- `data/normalized/characters`
- `data/manual/`
- `data/question_bank_ready.json`
- `data/question_bank_candidates.json`
- `data/question_bank_blocked.json`

### 数据变更后的标准动作

```bash
npm run prepare:data
npm run db:seed
```

如果涉及题库规则，请至少检查：

- ready 数量
- blocked 数量
- 搜索索引是否同步更新

## 四、代码变更后的标准动作

建议最少执行：

```bash
npm run lint
npm run test
npm run build
```

需要完整仓库校验时：

```bash
npm run ci:check
```

## 五、文档职责对应表

| 文档 | 维护重点 |
| --- | --- |
| `README.md` | 项目介绍、架构概览、部署入口、文档导航 |
| `docs/快速开始.md` | 首次拉起说明 |

| `docs/文档索引.md` | 文档用途与阅读顺序 |

## 六、GitHub 维护建议

### Issue

当前仓库建议使用模板：

- Bug report
- Feature request
- Documentation improvement

### Pull Request

提交 PR 前建议确认：

- 改动目标单一
- 文档已同步
- 关键校验已运行
- 没有把临时日志、缓存和构建产物带进仓库

### CI

CI 目前会执行：

- 安装依赖
- 仓库校验命令
- Docker 镜像构建验证

## 七、版本维护建议

- 小修复按 `fix:` 提交
- 新功能按 `feat:` 提交
- 文档更新按 `docs:` 提交
- 构建与自动化更新按 `build:` 或 `ci:` 提交

如果准备发布正式版本，建议同时更新：

- `CHANGELOG.md`
- README 的功能状态
- 对应部署文档
