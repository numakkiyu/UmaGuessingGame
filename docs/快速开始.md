# 快速开始

下载源码后，可在电脑或服务器上运行游戏。本页介绍首次启动、手机访问和容器部署，命令均在仓库根目录执行

## 环境

- Go 1.26.11 或兼容的新版本
- Node.js 24 与 pnpm 10.33.0，仅构建前端时需要
- GNU Make；Windows 可使用 WSL2 或下方等价命令
- Docker Compose v2 为可选部署方式

## 第一次启动

```bash
make web-install
make web-build
make embed-spa
make embed-spa-check
make content-compile
make content-verify
make dev
```

打开 `http://localhost:8080`，结束时在启动终端按 Ctrl+C。`make dev` 默认监听 `:8080` 并使用 `.cache/runtime`；这是开发用数据，不能当作永久备份

`make web-install` 会安装 `web/` 与 `web/tools/toolchain/` 两套锁定依赖，后者用于 ESLint、兼容解析器和 OpenAPI 类型生成。两套依赖均由各自锁文件管理

等价的 pnpm 命令：

```bash
pnpm --dir web install --frozen-lockfile
pnpm --dir web/tools/toolchain install --frozen-lockfile
pnpm --dir web run build
```

随后将 `web/dist/` 的完整内容替换到 `internal/spafs/dist/`，替换整个目录以清理旧构建文件，再运行：

```bash
go run ./cmd/content build --out content
go run ./cmd/content verify
go run ./cmd/server
```

直接运行默认监听 `127.0.0.1:8080`，数据在 `data/runtime`。Make 嵌入目标会同步完整前端产物

## 修改前端

一个终端运行后端，另一个终端启动 Vite：

```bash
pnpm --dir web run dev
```

打开终端显示的 Vite 地址，默认端口 5173。API 与题包头像由开发代理转发到后端，默认目标 `http://127.0.0.1:8080`；后端若配置了固定 Origin，需允许 Vite 实际地址。修改后要查看 Go 提供的页面，需再次 `make web-build`、`make embed-spa` 并重启 Go，Vite 热更新不会更新旧二进制中的页面

可用 `UMAGUESS_API_TARGET` 调整 Vite 代理目标，此变量只作用于前端开发服务器

## 手机与平板访问

确保设备在同一网络，防火墙允许所选端口，将下面地址换为电脑实际局域网 IP：

```bash
UMA_ADDR=0.0.0.0:8080 \
UMA_PUBLIC_ORIGIN=http://192.168.1.20:8080 \
UMA_ALLOWED_ORIGINS=http://192.168.1.20:8080 \
make dev
```

手机应打开 `http://192.168.1.20:8080`，不能打开手机自己的 `localhost`。浏览器离线缓存能力受安全上下文限制，HTTP 局域网访问不能视同 HTTPS 下的全部离线能力

## Docker

先在宿主机编译并校验内容包，再启动：

```bash
make content-compile
make content-verify
cp .env.example .env
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
```

`.env` 是 Compose 插值输入，不会被 Go 自动读取，且 Compose 只传入其 `environment` 中列出的变量。默认容器 Origin 为本机访问地址，其他设备访问必须同时修改 `UMA_PUBLIC_ORIGIN` 与 `UMA_ALLOWED_ORIGINS`

内容包只读挂载，运行数据与备份分别保存在命名卷。`docker compose down` 保留卷；不要使用删除卷的选项清理故障
