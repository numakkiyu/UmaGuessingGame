# 維護與更新

維護範圍包括程式、嵌入頁面、執行資料、簽章金鑰、內容包與設定

## 備份

開發環境使用 `make backup`。其他資料目錄可指定環境變數，容器則在 app 內執行備份指令

```bash
UMA_DATA_DIR=/srv/umaguess/runtime \
UMA_BACKUP_DIR=/srv/umaguess/backups \
go run ./cmd/server backup
```

```bash
docker compose exec app /app/uma-server backup --dir /backups
```

使用應用程式的一致性備份，勿直接複製執行中的 SQLite 主檔。`verified-keys.json` 與部署設定需獨立儲存，資料庫備份不代表包含所有外部檔案

## 更新程式

```bash
make web-install
make web-build
make embed-spa
make embed-spa-check
make content-compile
make content-verify
make build
```

保留原資料目錄，重啟服務。容器部署使用 `docker compose up -d --build`。同一資料目錄只允許一個服務程序，資料庫遷移由啟動流程執行

## 更新題庫

修改來源資料後重新執行內容編譯與驗證，`content/current` 指向新包，再重啟應用程式。已發布包保持唯讀，不直接覆蓋其中檔案。舊包可保留供回復使用

新包先在獨立執行目錄確認，檢查 `current` 指標與檔案摘要。發布前保留舊包及其設定，切換後確認健康狀態與開局。不要以刪除簽章金鑰處理連線問題

恢復備份前，先在獨立目錄檢查 SQLite 完整性、金鑰與內容版本，確認檔案權限屬於實際執行帳號。服務停止後才替換執行資料。連線恢復正常後，仍須確認舊憑證與舊長連線已失去存取權

## 回復

停止服務，保留故障資料，再以備份恢復。資料表遷移後，舊程式不一定能讀新資料，回復時使用相符的舊程式、遷移前備份、內容包與設定

不要刪除 WAL／SHM 或 Docker 資料卷來排除資料庫故障

## 常見問題

| 現象 | 處理方向 |
| --- | --- |
| 操作遭拒 | Origin 是否完全相符、HTTPS 與 Secure Cookie 是否一致 |
| 手機連不上 | 監聽位址、防火牆、同一網段、不要使用手機的 localhost |
| 畫面仍是舊版 | 重新建置前端、更新嵌入頁面並重啟 |
| 服務未就緒 | 內容包 current 指標、檔案摘要與權限 |
| 持續重連 | 代理 SSE 緩衝、閒置逾時、連線上限、網路切換 |
| SQLite locked | 重複程序、共用磁碟、磁碟延遲 |
| 玩法無法開局 | 部署開關、人數、內容報告與資料審校狀態 |
| Turnstile 持續失敗 | 主機名、站點鍵、金鑰是否傳入、出站 TLS 與操作名稱 |
| 單人紀錄消失 | 網址或瀏覽器是否更換、是否清除資料、是否有匯出檔 |

## 記錄與權限

`/health/live` 表示程序存活，`/health/ready` 表示可以提供服務。`/metrics` 預設只允許回環來源，反向代理須另外限制外部存取。日誌不包含 Cookie、憑證、答案和完整指紋

連線身分預設每 30 秒複核，退出與席位恢復另行撤銷舊連線。資料庫短暫故障可能延遲複核，連線失敗不自動判定玩家投降
