# 帳號登入與遊玩權限

帳號登入是實驗性功能，預設關閉，暫不建議啟用。設定完成後可使用第三方帳號登入，好友、派對、隨機配對可分別要求登入。普通單人挑戰不需登入

## 身分

外部身分以 `(issuer, client_id, subject)` 唯一對應內部 UUID。OIDC 使用驗證後的 `sub`，原生 OAuth 使用平台當前使用者介面的固定 ID。不同平台不自動合併，也不以暱稱、信箱、IP 或瀏覽器指紋合併

帳號 UUID、匿名遊玩會話 ID、房內六位編號各有用途。暱稱與頭像沿用全站設定，不由第三方顯示名稱覆寫

登入或登出前取消目前排隊並離開房間，轉移主持權、撤銷舊即時權限。進行中的個人對戰按投降處理，團隊成員退出不等於全隊投降。清理失敗保留原身分

要求登入的房間禁止同一帳號占用兩個席位或重複排隊；可匿名遊玩的入口仍採匿名規則

## 啟用

需要 HTTPS 網域、固定回呼網址、可信代理、提供方用戶端 ID 與金鑰，以及可連線的探索文件、公鑰與權杖端點

複製現有策略，在根物件加入 `accounts`。本地設定檔已由 Git 忽略，保留原玩法與容量設定

```sh
cp config/cloud.json config/accounts.local.json
```

```json
{
  "accounts": {
    "enabled": true,
    "publicUrl": "https://game.example.com",
    "requireLogin": {
      "friend": false,
      "event": false,
      "matchmaking": false
    },
    "idleSeconds": 86400,
    "absoluteSeconds": 604800,
    "providers": [
      {
        "id": "microsoft",
        "enabled": true,
        "protocol": "oidc",
        "issuer": "https://login.microsoftonline.com/YOUR_TENANT_ID/v2.0",
        "clientId": "MICROSOFT_CLIENT_ID",
        "clientSecretEnv": "UMA_MICROSOFT_CLIENT_SECRET"
      },
      {
        "id": "google",
        "enabled": true,
        "protocol": "oidc",
        "issuer": "https://accounts.google.com",
        "clientId": "GOOGLE_CLIENT_ID",
        "clientSecretEnv": "UMA_GOOGLE_CLIENT_SECRET"
      }
    ]
  }
}
```

範例中的網域、租戶與用戶端 ID 需替換。`publicUrl` 只接受不含路徑、查詢與使用者資訊的 HTTPS Origin，回呼不依請求 Host 拼接

金鑰放在 `clientSecretEnv` 指定的私密環境變數，不放 JSON、前端、Git 或記錄。在程序環境中設定金鑰後啟動

```sh
UMA_SECURE_COOKIES=true \
UMA_ALLOWED_ORIGINS=https://game.example.com \
UMA_ALLOW_MISSING_ORIGIN=false \
UMA_PUBLIC_ORIGIN=https://game.example.com \
go run ./cmd/server --config config/accounts.local.json --addr 127.0.0.1:8080
```

此指令啟動 HTTP 後端，由 HTTPS 反向代理轉發。安全 Cookie、精確 Origin 與可信代理設定見[設定參考](配置参考.md)

| 設定 | 行為 |
| --- | --- |
| 省略 accounts 或 enabled: false | 隱藏帳號入口，使用原匿名流程 |
| enabled: true，三種要求皆 false | 可自行登入，也可匿名參加 |
| requireLogin.friend | 好友遊玩必須登入 |
| requireLogin.event | 派對建立與參與必須登入 |
| requireLogin.matchmaking | 排隊、確認與配對對局必須登入 |

三種要求獨立。總開關關閉卻要求登入、缺少金鑰或探索失敗時拒絕啟動。啟用登入不會開啟原本停用的玩法

### Docker 與停用

Compose 不預設傳入帳號金鑰。另建本地覆寫檔，明確傳入變數與策略路徑

```yaml
services:
  app:
    environment:
      UMA_CONFIG: /etc/umaguess/accounts.local.json
      UMA_PUBLIC_ORIGIN: https://game.example.com
      UMA_ALLOWED_ORIGINS: https://game.example.com
      UMA_ALLOW_MISSING_ORIGIN: "false"
      UMA_SECURE_COOKIES: "true"
      UMA_GOOGLE_CLIENT_SECRET: "${UMA_GOOGLE_CLIENT_SECRET:?set in deployment environment}"
      UMA_MICROSOFT_CLIENT_SECRET: "${UMA_MICROSOFT_CLIENT_SECRET:?set in deployment environment}"
```

```sh
docker compose --env-file /absolute/private/accounts.env \
  -f docker-compose.yml -f /absolute/private/compose.accounts.local.yml config --quiet
docker compose --env-file /absolute/private/accounts.env \
  -f docker-compose.yml -f /absolute/private/compose.accounts.local.yml up -d --build
```

設定目錄已唯讀掛載，私密環境檔只留在部署環境。修改後重啟。停用時省略 `accounts`，或將 `enabled` 和三種 `requireLogin` 全設 false，再重建容器；既有帳號對應不會刪除

## 登入預設

| 預設 | 接入方式 |
| --- | --- |
| Google | OIDC，issuer 為 https://accounts.google.com |
| Microsoft | OIDC，使用指定租戶的 v2 issuer，不使用 common |
| GitHub | 原生 OAuth 2.0，讀取 /user 的數值 id；也支援 OIDC 代理 |
| X | 原生 OAuth 2.0 + PKCE，讀取 /2/users/me 的 data.id；權限 users.read tweet.read |
| QQ、Facebook | 透過提供對應登入方式的 OIDC 身分服務 |
| 其他帳號 | 標準 OIDC，可自訂名稱與圖示 |

回呼網址為 `publicUrl + /api/v1/account/callback/{id}`，須在提供方登記完全相同的網址

## 介面模板

只顯示已啟用的預設，依設定陣列排序。一個入口單欄，兩個或四個雙欄，其他數量桌面最多三欄、手機最多兩欄

自訂 OIDC 範例

```json
{
  "id": "club",
  "enabled": true,
  "protocol": "oidc",
  "issuer": "https://identity.example.com",
  "clientId": "CLUB_CLIENT_ID",
  "clientSecretEnv": "UMA_CLUB_CLIENT_SECRET",
  "displayNames": {
    "zh-Hans": "同好会账户",
    "zh-Hant": "同好會帳號",
    "ja": "サークルアカウント"
  },
  "iconPath": "/assets/ui/providers/club.svg"
}
```

ID 為 1–32 個小寫字母、數字與短橫線，以字母開頭，最多 12 個提供方。自訂名稱三語各 1–48 字，拒絕控制與文字方向字元

`iconPath` 限 `/assets/ui/providers/` 下的 SVG、PNG、WebP。圖示放進 `web/public/assets/ui/providers/` 隨前端發布，不接受外部 URL、data URL 或路徑穿越。缺圖用統一登入圖示

右上角原問候語在啟用時改為未登入／已登入，設定面板顯示登入按鈕。失敗使用橙紅色角色彈窗，等待時停用重複送出，動畫遵守減少動態設定

## 標準介面

| 方法與路徑 | 用途 |
| --- | --- |
| GET /api/v1/config | 公開登入方式與各模式登入要求 |
| GET /api/v1/account | authenticated、登入後的 UUID、期限與記憶體使用的 CSRF |
| POST /api/v1/account/logins/{providerId} | 提交 returnTo，取得授權網址 |
| GET /api/v1/account/callback/{providerId} | 消耗單次交易，303 返回本站 |
| POST /api/v1/account/renew | 延長活躍會話並輪替 Cookie |
| DELETE /api/v1/account/session | 撤銷本站登入，返回 204 |

`returnTo` 限 `/`、`/friends`、`/party`、`/matchmaking`。續期與登出需要 Cookie、Origin、`X-Account-CSRF`。帳號 CSRF 與匿名遊玩 CSRF 分開，不可互用

## 會話與安全

- 採授權碼流程與 S256 PKCE，state 綁定瀏覽器與提供方，五分鐘有效且僅可使用一次。OIDC 驗證簽章、issuer、audience、nonce、期限、授權方，以及提供時的存取權杖摘要，簽章演算法限 RS256／ES256
- 上游 access token 與 ID token 僅在後端本次請求使用，不寫入資料庫或回傳前端，也不申請離線更新權限
- Cookie 使用 `__Host-uma_account`，設 Secure、HttpOnly、SameSite=Lax、Path=/，省略 Domain。資料庫只儲存隨機 Cookie 的 SHA-256 摘要
- 閒置期限預設 24 小時，絕對期限預設 7 天。閒置可設 5 分鐘至 7 天，絕對期限介於閒置期限與 30 天之間；所有續期均受絕對期限約束
- 頁面可見時依剩餘期限安排續期，背景頁面不持續續期。滿 30 分鐘輪替 Cookie，舊值保留 30 秒供已送出的並行請求完成，條件更新避免舊 Cookie 被寫回
- CSRF 僅存於前端記憶體，不寫入 localStorage、sessionStorage、查詢字串或快取。後端重啟後可重新讀取帳號狀態取得新值
- 外部請求限可信設定中的公開 HTTPS 與 443 埠，拒絕私網、回環、雲端中繼資料位址、URL 使用者資訊與重新導向，並限制連線數、逾時與回應大小
- 登入交易最多 1024 筆；登入與回呼共用每 IP 每分鐘 30 次、突發 10 次限制，既有全站限流繼續生效
- 帳號回應不快取，回呼採 no-referrer。授權碼、state、token、完整 Cookie 與上游錯誤不寫入應用程式日誌；反向代理也須排除回呼查詢參數

登出僅撤銷本站會話，第三方網站的登入狀態獨立管理。現行服務採單實例 SQLite 與程序內登入交易，重啟後未完成的授權需重新開始。多實例部署需另外提供共享交易儲存與統一排程

## 挑戰賽與挑戰榜 beta

已有回應式介面元件，計分與排行榜 API 尚未接入，也沒有公開入口或後端開關。計分方案以單人經典猜角色為起點，題目、答案、剩餘次數、期限與成績均由伺服器確認，本地紀錄不匯入排名

候選規則為最多猜錯 8 次、每局 20 分鐘，正式規則與統計週期於計分 API 實作時確定

計畫路徑為 `/api/v1/scored-challenges` 及 `/api/v1/leaderboards/{boardId}/entries`、`/me`，尚未加入 OpenAPI 或註冊路由。詳見 [API](API与实时通信.md)
