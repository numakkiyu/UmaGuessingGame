# 題庫與內容編譯

角色資料、賽事關係與素材會在建置時整理成內容包，執行遊戲時直接讀取，不需即時擷取百科頁面

## 資料配置

| 路徑 | 內容 |
| --- | --- |
| `data/wiki/` | 角色、技能、原型與公開資料快照 |
| `data/manual/` | 欄位修訂、規則輸入與審校紀錄 |
| `data/assets/` | 已記錄來源的圖片與音訊 |
| `content/pack-*` | 編譯後的內容包，不加入 Git |
| `content/current` | 目前使用的內容版本指標 |

## 建置

在儲存庫根目錄執行

```bash
go run ./cmd/content build --root . --dry-run
go run ./cmd/content build --root . --out content
go run ./cmd/content verify
go run ./cmd/content current
go run ./cmd/content sections
```

`build --evidence <path>` 可輸出建置報告。`verify --dir` 指定個別內容包；省略時讀取目前的內容包，其他內容根目錄使用 `--out`

內容先寫入暫存目錄，完整後更新 `current`。已發布內容包維持唯讀，資料修正時建立新包

## 公開與私有資料

`public/` 放置可提供給瀏覽器的角色資訊、單人題目與圖片；`private/` 儲存連線對局答案、盤面及判題資料。應用程式依權限提供檔案，請勿直接公開整個內容包目錄

一般單人挑戰在瀏覽器作答，連線對局由伺服器出題並判定。處理範圍見[架構與模組](技术架构说明.md)

## 出題範圍

各玩法分別檢查必要欄位、素材、關係與審校狀態

- 經典猜角色的答案須能由提示區分，可猜角色與答案清單分開維護
- 適性棋盤須可由九位不同角色填滿九格
- 排序須有足夠有效資料，同值可並列，日期採明確的地區口徑
- 血統、賽事、路線、配對與拼圖的答案須包含在該題候選清單
- 語音須有有效檔案及內容審校紀錄

實作與參數見[內容模組說明](https://github.com/numakkiyu/UmaGuessingGame/blob/main/internal/content/README.md)

## 更新資料

修正時記錄角色、欄位、原值、新值與來源 URL。音訊審校紀錄須對應檔案摘要，圖片也須保留來源與授權資訊
