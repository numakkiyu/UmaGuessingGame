# 介面與互動

以明亮學園風格呈現遊戲，讓玩家先看見題目與操作，再閱讀補充資訊。配色參考官方與 BWIKI，實際版面依本遊戲的任務安排

## 資訊層級

依目前任務、主要操作、進度、輔助資訊與細則的順序安排畫面。等待、已送出、暫停、揭曉與結算須以文字區分，同一錯誤不重複出現在彈出視窗和常駐警告中

## 裝置版面

| 畫面 | 配置 | 檢查重點 |
| --- | --- | --- |
| 手機直向 | 單欄卡片、分段操作與易點選按鈕 | 螢幕鍵盤不遮住按鈕，長名稱可換行，操作不依賴滑鼠停留 |
| 手機橫向、低高度視窗 | 緊湊頁首，必要時使用雙欄 | 主要操作不超出可視高度 |
| 平板 | 比較表格，或主要內容與輔助分欄 | 觸控區足夠大，表格可讀 |
| 電腦 | 比較資料用表格，作答與補充資訊分區 | 作答與輔助資訊互不遮擋 |
| 大螢幕 | 唯讀賽況、遠距離可辨識文字 | 遠距離可讀，隱藏私有答案與操作 |

表格改為卡片後保留欄位意義、順序、狀態與操作。僅在需要雙向比較的區域提供水平捲動。長譯名與暱稱可換行，固定操作列預留高度及安全區域，鍵盤順序與畫面順序一致

## 元件與彈出視窗

按鈕、選單、對話框與表單錯誤使用共用元件，不使用 `alert`、`confirm`、`prompt` 處理遊戲操作。瀏覽器權限提示保留原有行為，必要時先說明用途，由玩家主動觸發

視窗開啟時移入焦點，關閉時回到觸發按鈕。Escape、取消與背景操作限制須一致，透過 Portal 與固定層級管理重疊關係

## 色彩與動態

色彩、間距、字級與動態由 `web/src/styles/tokens.css` 管理。判定同時使用文字或符號，透明背景須以實際合成效果確認對比度。裝飾圖片不打擾螢幕報讀

選取、翻牌、揭曉與名次變化使用短而清楚的回饋，優先使用變形與透明度。減少動態設定直接呈現可理解的結果，計時和裁決不依賴動畫播放結束

圖片失敗仍保留版面空間，背景與裝飾須避開題目、焦點及主操作

## 字型與字重

內文、按鈕、數字與標題使用思源黑體的地區字形。內文 400、標題與控制項 600，以字級、間距與顏色區分層級，程式碼區塊使用等寬字型
