# 安全政策

目前維護 V2 程式碼，舊架構的線上服務請向該部署維護者確認。本文說明實作與部署條件，安全及容量仍需依實際環境評估

## 漏洞回報

優先透過 GitHub **Security → Report a vulnerability** 私下回報。若未啟用，請在 Issue 詢問私密聯絡方式，勿公開攻擊細節或憑證，專案未承諾固定回應時間

請附受影響提交、部署方式、最小重現步驟、影響範圍與去識別日誌。勿掃描第三方實例、占用連線或下載他人私有資料

## 部署與秘密資料

公開服務使用 HTTPS、Secure Cookie，明確設定 Origin 與可信代理 CIDR，不無條件信任轉發標頭。資料庫位於本機磁碟，由單一程序持有；資料、金鑰、備份與環境設定和靜態服務分開

`/metrics` 預設只允許回環來源，由 `UMA_METRICS_LOCAL_ONLY` 控制；反向代理仍須明確限制外部存取，代理使用回環連線不等於請求者已獲授權。保留 HTTP、連線、佇列與輸入大小限制，使用非 root 容器和持久卷

`verified-keys.json` 隨資料庫保護與備份。輪替時先停服，保留舊鍵，加入 Base64URL 無填補的隨機 32 位元組金鑰，再切換 `active`，最多保留 8 鍵。舊鍵至少保留至最後相關票據到期後 24 小時，確認不再需要舊回執才移除

金鑰檔案損壞時，先保留原檔、停止服務並從備份排查；直接重建會使既有簽章憑據無法驗證

## 身分與對局

匿名 Cookie 是身分憑證，暱稱、房間代碼、六位編號、IP 與瀏覽器特徵都不等於身分認證。清除 Cookie 或更換瀏覽器可能建立新身分

單人答案與紀錄可從瀏覽器讀取，因此不匯入正式對戰成績。連線出題與裁決在伺服器執行，用戶端不能指定分數、勝負或期限。寫入交易內會重新確認會話、成員、角色與操作權

通知連線檢查完整成員關係，退出或恢復席位時撤銷，平時預設每 30 秒重新確認。敏感狀態與操作另有權限檢查，暫時資料庫故障不作為作弊證據

CSP、Origin、CSRF、HttpOnly Cookie 與輸入限制用於減少注入及非法請求，不因開發工具或擴充功能自動判負，也無法完全阻止查公開資料、自動解題或使用者控制自己的瀏覽器。大規模流量攻擊仍須代理或 CDN 保護

本地存檔的校驗和用於檢查損壞，正式成績依服務端裁決。通知連線只傳送變更訊息；會話到期或角色變更可能到下次複核才斷線，敏感資料讀取與操作仍逐次授權

## 選用入場確認

Turnstile 預設關閉，啟用時由伺服器透過 Siteverify 核對主機名、操作與期限。原始權杖與金鑰不進入公開設定或日誌，消費紀錄綁定會話並設期限與容量

異常判定採已認證會話自身的限流紀錄，成功確認不清空一般請求限額

驗證期間仍可取消本人配對、拒絕對局、退出或投降，這些操作均保留認證、Origin／CSRF、限流與歸屬檢查。接受對局、移除他人與佇列保活仍受異常確認限制。風險狀態與通行憑證版本一起更新；新異常使舊憑證失效，停用 Turnstile 後既有權限與容量限制繼續生效

## 帳號與更新

外部登入是預設關閉的實驗性功能，使用 HTTPS、固定回呼與後端環境變數。上游權杖僅在該次後端請求使用，帳號 Cookie 與匿名遊玩 Cookie 分開
