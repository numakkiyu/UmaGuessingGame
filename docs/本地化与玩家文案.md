# 本地化与玩家文案

项目支持简体中文 `zh-Hans`、繁体中文 `zh-Hant` 与日语 `ja`。繁体中文面向港台玩家，日语面向日本玩家，分别采用当地熟悉的表达，不能把简体文案逐字换成繁体或日语后就视为本地化完成

## 面向玩家表达

提示先说发生了什么，再说明玩家能做什么。普通流程不展示技术名词、部署位置、开发进度和内部标识；语气轻松直接，适当使用训练员、学园、队伍等熟悉称呼，不把每个按钮都写成梗

| 场景 | 建议表达 | 避免表达 |
| --- | --- | --- |
| 作答后等待确认 | 正在确认刚才的作答 | 正在重放幂等请求 |
| 房间已满 | 房间坐满啦，试试其他房间 | 达到 membership 容量限制 |
| 暂不能加入 | 暂时进不去，稍后再试 | 准入失败、队列仲裁拒绝 |
| 资料不足 | 这项玩法还缺可用的题目 | private section 未通过门禁 |
| 连接中断 | 连接断开了，正在重新连接 | SSE transport fallback |
| 姓名搜索 | 日文名、英文名、其他译名、外号 | 别名命中 |

提示必须符合真实状态：未收到确认不写“已经保存”，仍可恢复不写“全部丢失”，等待处理不写“操作失败”。状态与下一步能说清时，不额外添加长篇技术解释

严重故障可提供必要的错误编号和可展开诊断，方便玩家反馈；不要直接显示异常堆栈、Cookie、SQL、内部 ID、秘密答案和原始服务错误

## 语气与标点

按钮用具体动作，如“加入房间”“确认阵容”，不使用含糊的“执行”“提交请求”。简中可自然使用社区熟悉的称呼，但不使用带攻击、歧视或让新玩家无法理解的外号作为唯一说明

页面标题、标签、按钮及独立段落末尾省略句号。段落中间需要断句时保留正常标点，不删除小数点、版本号、URL 或代码中的标点。日语与繁体按各自语言习惯断句，不能为满足形式导致难读

免责声明说明资料可能缺漏、译名差异和反馈方法，不写给开发者看的准入流程。只显示与当前页面有关的信息，不在每个角色、每张卡片下面重复整段免责声明

## 角色名称

主名称独立一行，其他名称使用深灰色在下一行连续排列，以顿号分隔，不为每种来源增加一整行标签。不要把来源词、命中类型或技术状态夹在名字之间

- 简中：其他别名 → 日文原名 → 英文名 → 外号
- 繁中：其他译名 → 日文原名 → 英文名，不加入简中外号
- 日语：日文原名优先，再展示英文，不混入简繁中文名称和外号

删除与主名称重复的项，对同一项去重，同时保留有意义的括号原文。名称应来自有来源的资料，不因拼写相似、原型同名或机器转换而虚构官方译名

## 地区适配

繁中用词需考虑港台常见游戏表达、官方地区名称及阅读习惯；日语使用自然的游戏 UI 语序、敬体与常见按钮表达，不保留直译中文的冗长句式。遇地区差异较大时优先清楚中性的写法，必要时由对应地区玩家审校

日期、数字、倒计时和计分使用统一格式工具。角色名、队伍名和玩家输入不能当作翻译键，缺失翻译不向玩家展示资源路径或键名。语言切换不得改变当前题目、已确认选择、截止时间或房间身份

## 资源与验证

资源文件位于前端的语言目录，新增提示覆盖简繁日三套内容，并检查插值变量、单复数/计数、ARIA 文案、错误后的下一步与长度变化。禁止把技术错误统一替换成一句“未知错误”而丢掉恢复指引

```bash
make web-copy-check
make web-test
make web-typecheck
```

自动扫描只能发现部分禁词与结构问题，不能证明文案自然。发布前需由相应地区玩家确认称呼、语气和实际页面排版，特别检查手机窄屏、按钮、下拉菜单与弹层是否截断

相关要求见[界面与交互规范](界面与交互规范.md)及[测试与质量检查](测试与质量检查.md)
