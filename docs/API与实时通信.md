# API 与实时通信

[api/openapi.json](https://github.com/numakkiyu/UmaGuessingGame/blob/main/api/openapi.json)是 HTTP 契约源，[api/realtime.schema.json](https://github.com/numakkiyu/UmaGuessingGame/blob/main/api/realtime.schema.json)描述实时消息。本文解释调用顺序与恢复语义，具体字段、枚举、错误和操作要求以契约及路由校验为准

## 基础约定

资源位于 `/api/v1`，使用 JSON 与 camelCase 字段，ID 为不透明字符串。错误使用 RFC 9457 `application/problem+json`，客户端按稳定错误类型处理，不将原始数据库或验证错误直接显示给玩家

会话创建、验证回调等引导接口与普通业务写入存在不同前置条件，调用者逐操作读取契约，不能无条件向每个请求塞同一组头。普通已认证写入按契约提供 Cookie、`Origin`、`X-CSRF-Token` 与 `Idempotency-Key`，必要时附阶段及状态版本

## 典型调用顺序

1. 读取公开配置、玩法可用性与角色搜索资料
2. 创建或恢复匿名会话，获取本次可用的 CSRF；刷新时旋转 CSRF 不应更换玩家身份
3. 按部署要求完成入场验证，创建房间或解析邀请码并加入
4. 读取房间与对局快照，依据服务端能力字段显示操作
5. 通过 REST 提交动作，保留命令键和已知版本，等待确认
6. 订阅通知并按游标恢复，必要时重新读取快照，最终以结算数据展示成绩

昵称与房间编号只用于展示，不用于授权。主持、队伍控制和大屏读取均由服务端成员与授权关系确定，不能因前端按钮隐藏就跳过后端检查

## 重试与结果不确定

同一个逻辑命令重试时复用原幂等键和内容；新的逻辑命令使用新键。网络超时不能证明服务端没有提交，客户端应查回执或读取快照，避免自动产生第二次动作

遇阶段或版本冲突，先恢复最新状态再决定是否仍能提交。遇限流或队列满，遵循退避提示，避免每个组件自行不断重试。取消前端请求也不能撤销已经提交的数据库事务

这些词用于开发文档，普通玩家文案应表达“正在确认刚才的作答”“请稍后再试”等实际状态，不展示“重复使用相同幂等键”之类内部说明

## 实时连接

前端默认 SSE，可选优先 WebSocket，失败后使用游标轮询。实时通道用于下行通知，动作仍走 REST。SSE 使用命名事件，客户端需逐一注册；只监听默认 message 会漏掉业务通知

每个房间保持受控主通道与在途恢复请求，断线后关闭旧连接并按退避重连，不能因页面多次挂载累积订阅。收到新 epoch、游标过期或恢复要求时读取快照，不能凭旧事件拼出未授权私有状态

反向代理必须支持 SSE 流式响应并禁用对应路径缓冲，正确转发 WebSocket Upgrade，设置合适超时。健康端点成功不说明代理后的实时流一定可用

## 公开与私有状态

服务端按观看者角色与回合阶段投影，答案、队伍私有线索与未公开投票不提前下发。客户端缓存不应混用不同身份的房间数据；浏览器 Service Worker 不能缓存认证 API、私有投影或实时连接

公开练习资料与竞赛秘密资料的信任边界不同，不能因为单人挑战需要答案就将比赛私有 section 公开

## 修改契约

```bash
make web-api-types
pnpm --dir web run api:check
go run ./cmd/content contract --spec api/openapi.json --routes
```

生成文件是 `web/src/lib/api/schema.d.ts`，不要手改生成内容。新增路由同时更新契约、实现、动作分发和真实装配测试。项目的 Go 校验器检查引用、路径、操作、写入头、模式判别与路由一致性，不是完整的 JSON Schema 验证器，不能据此宣称全部 OpenAPI 语义都已被验证

## 匹配大厅接口

| 方法与路径 | operationId | 用途 |
| --- | --- | --- |
| `GET /matchmaking-lobby` | `getMatchmakingLobby` | 读取开放队列及真实人数汇总，大厅关闭返回 403 |
| `POST /matchmaking-proofs` | `createMatchmakingProof` | 会话与 CSRF 保护，提交 `poolId`，获得 90 秒有效挑战 |
| `GET /matchmaking-tickets/current` | `getActiveMatchmakingTicket` | 恢复本会话唯一活动票据，没有时返回 `{ "ticket": null }` |
| `POST /matchmaking-tickets` | `createMatchmakingTicket` | 提交 `poolId`、`proof.challengeId`、`proof.nonce`，原子消费挑战并创建票据 |
| `POST /matchmaking-tickets/{ticketId}/heartbeat` | `heartbeatMatchmakingTicket` | 当前票据所有者续约在场租约，不延长确认期限 |
| `POST /matchmaking-tickets/{ticketId}/responses` | `respondToMatch` | 明确接受或拒绝，全部确认后自动准备并启动回合 |
| `DELETE /matchmaking-tickets/{ticketId}` | `cancelMatchmakingTicket` | 取消尚未进入房间的票据，比赛开始后通过房间离开 |

以上路径以 `/api/v1` 为前缀，数据结构以 `api/openapi.json` 为准。票据创建、接受/拒绝和取消保留 `Idempotency-Key`；结果不确定时原样重试相同请求体与键。创建身份与票据在同一事务保存，防止业务已成功但 HTTP 回执丢失后重复消费挑战

挑战验算：对 UTF-8 字符串 `challengeId + ":" + nonce` 计算 SHA-256，要求指定数量的最高有效位为零。`nonce` 是不超过 16 位的十进制无符号整数文本，服务端按原文本验算。挑战发放和心跳属于短时租约操作，不保存通用幂等回执；重复发放替换本会话旧挑战，重复心跳只续约现有票据，不创建新资源

票据状态依次为 `queueing`、`matched-pending-accept`、`ready`、`playing`；`ready` 且没有 `roomId` 只说明本人已确认。前端必须继续读取，直到获得房间再进入。取消、过期和结束分别使用 `cancelled`、`expired`、`finished`。一个玩家的队列、房间和回合分配在 SQLite 写事务中完成，不能与另一个匹配重复分配

随机房间只接受已匹配成员，邀请码不可用，所有玩家均无房间管理权限。自动准备可以从中断状态恢复，60 秒内无法完成的准备会取消房间以释放参与者。公开人数不包含会话、成员、分组或工作量凭证标识

### 空闲回收与提交时间边界

匹配大厅增加 `idleSeconds` 汇总字段：`0` 表示未启用空闲回收，其他值为开放作答后的等待秒数。清理任务与提交共享房间命令队列，并在写事务中复核回合状态和已接受提交。空闲超时后才收到的首次作答返回 `409 matchmaking-idle`；已经持久化的相同提交仍按原回执重放

`received_at` 是服务端在命令入队时赋予的时间，不接受客户端提供的计分时间。正常比赛截止和空闲截止均用它判断；服务端统一校时，客户端倒计时仅作展示。不因为心跳、失败请求或改动客户端时钟重置比赛时限

对手进度复用各玩法 `publicState.subjects` 和 `subjectNames`，通过现有 `state.changed` 通知重新获取授权投影，不建立额外实时连接。网络档位复用轮询耗时，流式通道每约 20 秒进行一次轻量探测；后台页暂停探测、同一时刻最多一个探测，失败时显示连接状态。测量使用 `performance.now()`；档位不会发回服务端参与裁决

### 浏览器端安全边界

静态入口启用 Content Security Policy：限制脚本来源为本站与可选 Turnstile 官方域，不允许内联脚本或 `eval`，禁用对象嵌入、页面被框架嵌入及任意 base 地址，允许本站 Worker 和组件必要的内联样式。反向代理部署须保留这些响应头，并保持资源与 API 同源；开发服务器使用自己的开发策略

该策略降低常见网页注入风险，不能控制用户安装的特权扩展、开发者工具或设备本身。接口地址属于公开协议，不用随机改名或可逆前端加密作为身份验证。授权、会话、Origin/CSRF、回合版本、操作合法性、限流和一次性入场证明均在服务端检查

不使用打开 F12、窗口尺寸差、浏览器指纹或疑似脚本信号自动判负；它们既可绕过，也会误伤分屏、缩放、辅助工具及正常调试。拒绝非法请求与认定整局作弊是不同结论；目前对证据不足的情况不判负，无法完全阻止自动化工具或场外辅助

## 回合操作权限与结果一致性

`RoundView.canSubmit` 同时受参赛资格、当前代表、暂停、阶段、截止时间、认输状态及玩法自身限制影响。前端以该权限控制交互；服务端在实际写入时重新校验，页面缓存不构成提交许可。只有作答阶段以及该玩法允许的准备阶段能够提交，收卷、揭晓、结算和取消阶段均关闭提交

认输后的新提交返回 `participant-surrendered`，不能覆盖已有认输标记。创意投票使用独立投票记录时仍需检查实际参赛者的认输状态。换卡的提案和回应都检查双方资格，对已认输者发起的未成交提案返回 `trade-closed`。截止后的认输、暂停申请或暂停接受返回 `deadline-passed`

同一已接受操作的合法重试可以读取原回执，但不再次执行操作；重试与认输后的新操作应分别处理

`results[].scoreUnits` 是该主体的正式计分结果，包含认输清零等修正，不能被 `publicState.self` 中的答题进度覆盖。读取正式成绩时需要同时核对 `subjectId` 和揭晓／结算阶段，0 是有效成绩。取消回合不返回正常结算结果

`results[].outcome` 遵守 OpenAPI 的枚举：`won`、`lost`、`draw`、`completed`、`surrendered`、`disconnected`、`void`。经典猜中或对手认输获胜使用 `won`，猜错次数用完且未获胜使用 `lost`，主动认输使用 `surrendered`；仅完成计分的其他结果使用 `completed`。`solved` 与 `failed` 可以描述答题事实，但不是此字段的取值，也不能代替其他多人赛制的排名判定

## 连接与请求保护

HTTP 请求会先经过地址级请求预算，再进行会话查询；无效 Cookie 不会绕过这道预算。认证后的请求还会按会话、动作和所属房间或回合分别计算额度，同一局的请求不会占满其他房间的额度。超过额度会收到可等待后重试的提示

普通请求有并发上限，实时连接有独立的总连接数、单房间连接数、单会话连接数和握手并发数。WebSocket 只接受心跳与游标确认帧，帧大小和频率均有限制；SSE 写入也受连接期限保护，慢客户端会被释放。浏览器断网、页面离开或服务端返回撤权后，前端会取消旧请求并停止旧通道，恢复时使用游标重新同步

## 开局元数据与恢复一致性

`GET /modes` 的 `Mode.startRule` 提供开局条件类别：`standard`、`clue-puzzle`、`rapport`、`trade`、`strategy-race`。它用于前端提前展示人数、分队和队长要求，不代替服务端在开始事务中的复核。`minPlayers` 与 `maxPlayers` 描述人数边界，队伍结构仍需结合 `startRule`、当前成员及玩法配置检查

暂停申请记录提交时的阶段版本，以实际计分主体区分双方。申请人或同一计分队伍回应返回 `pause-counterparty-required`，重复回应返回 `pause-request-closed`，阶段变化后的回应返回 `pause-request-stale`。拒绝与接受使用相同的权限和时效检查

兑换席位恢复码时，新会话创建、恢复码消费、原成员绑定、当前房间管理授权和活动主持身份的转移在同一 SQLite 写事务内完成。保留原 `membershipId`、队伍、房间编号及已接受进度；任一步失败均回滚，成功提交后再发送新 Cookie。旧浏览器失去该房间席位，旧控制租约失效，其他房间的身份不因此被全局撤销

内容素材回退服务只开放受支持的惰性图片、音频和视频扩展名，使用受限目录打开文件，禁止符号链接跳出素材根目录；保留 HEAD 与 Range 行为。HTML、脚本、SVG、JSON 和数据库文件不能通过该回退路径提供。前端正式静态产物仍由独立的 SPA 静态路径提供

无实时 Hub 时的 SSE 回退在写入流响应头之前验证游标；查询参数未提供时读取 `Last-Event-ID`。SSE 帧拒绝带换行的事件名，游标标识中存在 CR、LF 或 NUL 时不写入 `id:` 行，避免改变帧结构

随机匹配装饰由真实票据状态驱动，路由切换前先覆盖画面，再加载房间，展开完成后释放遮罩。失败或主动退出使用红色流光；图片、动画模块或图形渲染不可用时，仍须保留确认、取消和进入房间的路径。装饰不修改票据结果、判胜、服务端时间或作答窗口

JSON 请求必须是单个对象，字段不能重复，嵌套深度有限，未知字段仍按接口契约拒绝。数据库查询使用参数绑定；来源校验同时检查协议和主机，跨站请求不会因为伪造路径、查询串或协议名而通过。传输加密由 HTTPS/WSS 终止层负责，应用层签名只用于一次性凭证完整性，不替代授权或 TLS

部署到公网时请启用 HTTPS、Secure Cookie 和可信来源列表，并在反向代理或 CDN 配置连接数、请求体、连接建立速率和基础洪泛防护。局域网可按场地人数调整限额，但仍保留会话和动作级限制；共享出口地址不会单独决定玩家身份

## 授权生命周期

生产装配为实时 Hub 安装完整身份复核器，校验房间有效性、成员有效性、成员所属会话、角色，以及会话撤销和到期。保留成员 ID 的设备恢复不代表旧会话继续拥有席位。注册后立即复核以缩小握手与注册之间的竞态窗口，默认 30 秒周期复核；退出会话主动撤销全部连接，恢复设备仅撤销旧会话在原席位上的连接，不影响其他房间或新会话

恢复事务的 outbox 可包含 `revokeRoomSessionId` 和 `transferredMembershipId`，仅供服务端精确撤权，不进入实时客户端消息与重放包。通知投递后客户端仍需读取授权快照。无 Hub 的 SSE 回退同样要求实际成员并持续检查会话与成员绑定；查询失败暂停业务通知，不以数据库故障误判玩家作弊

写事务重新核对入队时的成员角色、队伍、会话绑定和会话有效期。状态已变化时拒绝旧请求，客户端应恢复当前授权后再操作，不能自动改用另一身份重发。合法回执重放不重新执行动作

请求保留地址、会话与动作限额；共享房间额度仅对该房间的有效成员或所有者计入。回合与活动路径先解析到真实房间，未授权者知道资源 ID 或提交错误邀请码也不能消耗该房间的共享额度。此规则不免除未授权请求本身的限流

## 入场状态与异常确认

`GET /api/v1/sessions/current/admission` 返回 `{ enabled, required, verified }`，不会创建身份、延长验证有效期或返回风险分数。没有有效会话时 `required`、`verified` 均为 `false`。`required` 表示后端要求当前会话重新确认；`verified` 表示现有签名凭据仍然有效

`GET /api/v1/config` 的 `admission.adaptiveEnabled` 说明自适应检查是否开启。`POST /api/v1/sessions/current/admission` 继续要求有效会话、Origin 与 CSRF，并由后端调用固定的 Cloudflare Siteverify 地址，校验成功标志、主机名、动作和挑战时间。客户端成功回调不能代替后端验证

`admission-required` 用于配置要求的普通入场；`admission-risk-required` 用于连续触发会话自身限流后的重新确认，均在业务处理前返回 403。客户端只对确定被拒绝的读取或携带原幂等凭据的写入恢复一次，保留原请求体；第二次被拒绝、未知写入结果及无幂等凭据的写入不会自动循环重放

身份读取与 CSRF 恢复共享独立的会话恢复限额（每分钟 24 次、突发 8 次），并受地址限额保护；验证提交沿用独立入场限额。业务操作拥堵不会耗尽验证所需的全部恢复路径。验证不会恢复已经失效的身份，也不会改变当前对局的裁决

令牌原文不持久化。应用按令牌摘要记录短时占用与消费状态，同一令牌不能跨会话使用；请求未明确完成时，仅原会话可以重试，并向提供方复用稳定的 `idempotency_key`。成功消费后拒绝重复消费，已有有效通行 Cookie 的恢复无需再次消费令牌。此本地防重放用于覆盖提供方重复令牌检测的传播窗口

## 实验性账户接口

账户接口为实验性功能，默认关闭。配置和使用方法见[账户登录与游玩准入](账户登录与游玩准入.md)

已实现的路径为 `/api/v1/account`、`/api/v1/account/logins/{providerId}`、`/api/v1/account/callback/{providerId}`、`/api/v1/account/renew` 和 `/api/v1/account/session`，方法、字段及错误以 OpenAPI 为准。账户 Cookie 与 CSRF 独立于匿名游玩会话；要求登录的玩法在 REST、恢复和实时连接中统一校验，配对展示身份仍只读

`GET /api/v1/config` 的 `accounts.providers` 只包含已启用且初始化完成的提供方，按配置顺序排列。公开字段仅含受限 ID、可用性、三语 `displayNames` 和本地 `iconPath`，不返回 issuer、客户端 ID、密钥变量名或令牌。修改展示字段不会获得账户权限
