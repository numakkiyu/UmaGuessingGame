# 文档站维护

项目使用 VitePress 提供简体中文、繁体中文和日语文档，README 保持 GitHub 原生 Markdown 格式

## 文件结构

| 路径 | 用途 |
| --- | --- |
| `README.md` | 简体中文项目介绍 |
| `README.zh-Hant.md`、`README.ja.md` | 繁体中文与日语介绍 |
| `docs/*.md` | 简体中文文档 |
| `docs/zh-Hant/` | 港台繁体中文文档 |
| `docs/ja/` | 日语文档 |
| `docs/.vitepress/config.mts` | 语言、导航、搜索和部署路径 |
| `docs/.vitepress/theme/` | 首页与主题样式 |
| `docs/public/media/` | 真实游戏截图与介绍图片 |

对应文档保持相同文件名，语言菜单可以切换到同一篇文章。角色名称与叙述按各地区玩家习惯维护，代码标识和 API 字段保持原样

## 本地运行

在仓库根目录执行

```bash
pnpm --dir docs install --frozen-lockfile
pnpm docs:dev
```

打开终端显示的地址。文档依赖与游戏前端分开安装，不改变游戏构建流程

```bash
pnpm docs:check
pnpm docs:build
pnpm docs:preview
```

默认路径为 `/UmaGuessingGame/`。自定义域名或其他仓库名可通过 `DOCS_BASE` 调整，例如

```bash
DOCS_BASE=/ pnpm docs:build
```

## GitHub Pages

工作流位于 `.github/workflows/pages.yml`，从 `docs/` 安装锁定依赖，构建后上传 `docs/.vitepress/dist/`

在仓库 Settings → Pages 中将 Source 设为 GitHub Actions。`main` 的 CI 通过后自动发布对应版本；手动运行 Pages 工作流也要求当前主线 CI 已通过。站点路径由 Pages 设置读取

GitHub Pages 提供文档网站。游戏服务按[快速开始](快速开始.md)单独部署，文档站不提供联机 API

## 图片与排版

README 使用相对图片路径、表格、`<picture>` 和折叠区。GitHub 不执行自定义 CSS、脚本或嵌入式网页，复杂首页布局放在 VitePress 主题中

游戏截图来自当前页面，项目 Logo 和 16:9 主视觉分别使用 `public/media/party-logo.webp` 与 `party-keyvisual.webp`，三种语言共用无字插画。游戏中的 Logo 副本位于 `web/public/assets/ui/branding/`，替换时同步更新并保留相同文件摘要。替换截图时保留相同语言对应关系，不将本地运行地址、私人账户或测试弹窗放入介绍图

## 内容维护

首页与 README 先介绍玩法和使用方式，协议、配置字段和 API 放到子页面。功能状态按实现描述，实验性功能注明默认开关；尚未接入的接口与可用接口分别说明

生成目录、依赖缓存和运行报告不加入 Git。素材出典与许可见[资料来源](第三方依赖与资料来源.md)

## 玩法图文与字体

`docs/play/`、`docs/zh-Hant/play/`、`docs/ja/play/` 分别保存三语玩法指南，每项包含操作步骤、规则与手机画面。截图位于 `docs/public/media/play/`，按玩法、语言与设备命名

字体位于游戏和文档各自的 `public/fonts/`。字形按地区选择，常用字优先加载，扩展字按需加载；来源与许可见[资料来源](第三方依赖与资料来源.md)
