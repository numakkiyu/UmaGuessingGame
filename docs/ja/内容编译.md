# 問題データのビルド

キャラクター情報、レースの関係、画像と音声をビルド時にコンテンツパックへまとめます。ゲームの実行中に百科事典のページを取得する必要はありません

## データの配置

| パス | 内容 |
| --- | --- |
| `data/wiki/` | キャラクター、スキル、実在馬などの資料スナップショット |
| `data/manual/` | 修正データ、ルールの入力、内容確認の記録 |
| `data/assets/` | 出典を記録した画像と音声 |
| `content/pack-*` | ビルド済みパック。Git の対象外 |
| `content/current` | 使用するパックを示すポインター |

## ビルド

リポジトリのルートで実行します

```bash
go run ./cmd/content build --root . --dry-run
go run ./cmd/content build --root . --out content
go run ./cmd/content verify
go run ./cmd/content current
go run ./cmd/content sections
```

`build --evidence <path>` はビルドレポートを出力します。`verify --dir` で特定のパックを選択でき、省略時は現在のパックを使用します。別のコンテンツルートは `--out` で指定します

パックを一時ディレクトリーへ書き込み、完成後に `current` を更新します。公開済みパックは変更せず、修正時は新しいパックを作成します

## 公開情報と非公開情報

`public/` にはブラウザー向けのキャラクター情報、一人用問題、画像を配置します。`private/` はオンライン対戦の正解や盤面など、判定に必要な情報を保持します。アプリケーションが権限に応じて配信するため、パックのディレクトリー全体を Web 公開しないでください

通常の一人用モードはブラウザー内で進行します。オンライン対戦はサーバーが出題・判定します。[構成とモジュール](技术架构说明.md)で処理の範囲を説明しています

## 出題できるデータ

種目ごとに必須項目、素材、関係、内容確認の状態を調べます

- キャラクター当てはヒントで区別できる正解を使い、回答候補と正解候補を分けて管理
- 適性マス埋めは異なる九人で全マスを埋められる問題を作成
- 並べ替えは有効な数値と日付を使用し、同値は同順位として扱う
- 血統、着順、経路、ペア、パズルの正解は、その問題の候補に含める
- 音声は再生可能なファイルと内容確認の記録が必要

詳しい判定は[コンテンツモジュール](https://github.com/numakkiyu/UmaGuessingGame/blob/main/internal/content/README.md)を参照してください

## 資料の更新

対象、項目、変更前後の値、出典 URL を記録します。音声の確認記録はファイルのダイジェストに結び付け、画像にも出典とライセンス情報を残します
