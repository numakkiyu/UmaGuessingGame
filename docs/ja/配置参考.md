# 設定リファレンス

設定はデプロイ JSON、プロセス引数、Compose 変数展開に分かれます。Go は `.env` を自動では読み込みません。Compose は `environment` に記載した変数だけを渡します

## 優先順位

設定ファイルは `--config` が `UMA_CONFIG` より優先します。上書き対応項目は JSON、環境変数、明示的なコマンド引数の順です。不明な JSON 項目と型違いは拒否し、変更は再起動で反映します

```bash
UMA_SECURE_COOKIES=true \
UMA_ALLOWED_ORIGINS=https://uma.example.com \
go run ./cmd/server --config config/cloud.json --addr 127.0.0.1:8080
```

コンテナー内の設定パスは `/etc/umaguess/cloud.json` で、ホスト側はマウント先により異なります。全引数は `go run ./cmd/server --help` で参照できます

## 環境変数

Go を直接起動した場合の既定値です。Make と Compose は保存先や待ち受けを変更する場合があります

| 変数 | 既定値 | 用途 |
| --- | --- | --- |
| `UMA_ADDR` | `127.0.0.1:8080` | HTTP 待ち受け |
| `UMA_DATA_DIR` | `./data/runtime` | DB・ロック・署名鍵 |
| `UMA_CONTENT_DIR` | `./content` | 問題データのルート |
| `UMA_WEB_DIR` | `./web/dist` | フロントエンドの保存先 |
| `UMA_BACKUP_DIR` | `./backups` | バックアップの出力先 |
| `UMA_DEPLOYMENT` | `lan` | デプロイ方式。JSON で指定可能 |
| `UMA_LOG_LEVEL` | `info` | ログレベル |
| `UMA_SECURE_COOKIES` | `false` | HTTPS 公開時は true |
| `UMA_ALLOWED_ORIGINS` | `—` | 完全な Origin をカンマ区切り |
| `UMA_TRUST_PROXY` | `false` | 指定プロキシの転送ヘッダーを信頼 |
| `UMA_TRUSTED_PROXY_CIDRS` | `—` | 信頼するプロキシの CIDR |
| `UMA_ALLOW_MISSING_ORIGIN` | `false` | 管理された非ブラウザー書き込みの例外 |
| `UMA_METRICS_LOCAL_ONLY` | `true` | メトリクスをループバックに制限 |
| `UMA_SESSION_TTL` | `168h` | 匿名セッションの期限 |
| `UMA_DISPLAY_TTL` | `12h` | 表示セッションの期限 |
| `UMA_BUSY_TIMEOUT` | `1s` | SQLite の待機時間。Go duration |
| `UMA_SYNCHRONOUS` | `FULL` | SQLite の永続化設定 |
| `UMA_READ_CONNS` | `8` | 読み取り接続プール |
| `UMA_QUEUE_CAPACITY` | `128` | ルーム別コマンドキュー |
| `UMA_SHUTDOWN_GRACE` | `15s` | 正常終了の待機時間 |

公開 URL は `UMA_PUBLIC_ORIGIN`、許可する接続元は `UMA_ALLOWED_ORIGINS` に明示します。信頼するプロキシは実際の範囲のみ指定し、`0.0.0.0/0` や `::/0` は使いません。コンテナーとホストではプロキシの接続元が異なる場合があるため、実際の接続元を確認します

## 種目の切り替え

`config/lan.json` は管理された LAN、`config/cloud.json` は公開サービス向けの控えめな設定です。`forms` の `local`、`verified`、`solo`、`friend`、`matchmaking`、`event` は、一人用、既存の検証型チャレンジ、一人用ルーム、フレンド、ランダム対戦、イベントを制御します。`modes` で種目ごとにも指定できます

いずれかが無効なら新規入口を制限し、人数と問題データの条件も適用します。Cloud はランダム対戦とイベントが既定で無効です。アカウントのランキング機能は `forms.verified` とは別です

## 容量

| limits | LAN | Cloud | 適用範囲 |
| --- | --- | --- | --- |
| `connections` | 2000 | 300 | サイト全体の接続 |
| `connectionsPerRoom` | 220 | 32 | ルームごとの接続 |
| `connectionsPerSession` | 2 | 2 | セッションごとの接続 |
| `playersPerRoom` | 100 | 16 | ルームごとの参加者 |
| `spectatorsPerRoom` | 100 | 12 | ルームごとの観客 |
| `queuedCommands` | 4096 | 512 | サイト全体の処理中・待機コマンド |
| `rateLimitBuckets` | 20000 | 10000 | サイト全体の制限バケット |
| `verifiedChallenges` | 512 | 128 | 進行中の検証チャレンジ総数 |
| `sessionCreatePerIPMinute` | 600 | 120 | IP ごとの毎分セッション作成 |
| `sessionCreatePerIPBurst` | 200 | 30 | IP ごとのセッション作成バースト |

保護上限の設定値で、実際の処理性能を示す数字ではありません。同じ IP を複数人が共有する場合があるため、IP を本人性には使いません

`limits.apiRequests` は通常リクエストの同時数、`requestPerIPMinute` と `requestPerIPBurst` は接続元の頻度を制限します。常時接続には全体・ルーム・セッションの上限を設け、公開時は CDN、リバースプロキシ、WAF も利用できます

## ランダム対戦

```json
{
  "matchmaking": {
    "lobbyEnabled": true,
    "queueCapacity": 1000,
    "proofBits": 16,
    "idleEnabled": true,
    "idleSeconds": 60
  }
}
```

`lobbyEnabled` はロビーと公開集計、`forms.matchmaking` は新規待機を制御します。`queueCapacity` は既定 1000、最大 10000。`proofBits` は既定 16、範囲 12–20 で、0 は既定値です。作業量証明は常に必要です

作業量証明は現在のセッションとルールに結び付き、有効期間 90 秒、一回限りです。Worker で SHA-256 を計算します。待機 120 秒、参加確認 20 秒、在席リース 35 秒を 3 秒ごとに更新し、取消や確認切れには 15 秒の待機時間があります

`idleEnabled` は既定 true、`idleSeconds` は既定 60、範囲 15–300。回答開始後に誰も有効回答を送らない場合だけ勝敗なしで取り消します。フレンドとパーティーには適用しません

ロビーは 5 秒ごとに集計を取得し、サーバーのキャッシュは最大 2 秒です。表示するのは待機・確認・対戦の人数とルーム数だけです

## Cloudflare Turnstile

`turnstile.enabled` は既定 false。有効時に `siteKey` と `hostnames` を設定し、秘密鍵は `secretEnv` の環境変数から読みます。既定名は `UMA_TURNSTILE_SECRET` です

`operations` はルーム作成・参加・待機・チャレンジ・イベントの確認対象、`grantSeconds` は既定 900、範囲 60–3600、`maxConcurrent` は同時検証数です。`browserSignals`、`signalPerMinute`、`signalBurst` は任意の補助情報と頻度設定です

適応確認の `adaptive` は既定 true、`riskThreshold` は既定 6、範囲 3–100、`riskWindowSeconds` は既定 60、範囲 10–600。認証済みセッション自身への頻度制限だけを使い、共有 IP、拡張機能、開発ツールで敗北判定はしません

通常は明るい確認カード、異常時は暗い背景と赤い縁の案内を使います。公式ウィジェットの内部 CSS や表示を改変せず、ロゴも隠しません。無効時はスクリプトと空き領域を作りません

### ウィジェットの外観と画面変更

公式の明るいテーマと `appearance: "always"` を使用し、周囲のカード・イラスト・状態表示をサイト側で整えます。Cloudflare の `interaction-only` と Enterprise Offlabel は公式の選択肢ですが、現行画面では採用していません

未完了時のサイズ変更ではウィジェットを準備し直し、完了済みや送信中の結果は保持します。閉じる操作やページ移動で古い復元処理を止め、新しい画面への上書きを防ぎます。マウント後 45 秒間、結果も手動チャレンジもない場合は再試行と戻る操作を表示します。手動チャレンジ中はこの準備タイムアウトで中断しません

## Compose

`UMA_HOST_PORT` は既定 8080、コンテナー内は `:8080`。追加の秘密変数は Compose から明示的に渡します。`UMA_RUNTIME_IMAGE` と `UMA_BUILD_GO_PROXY` はビルド時の引数です。実行イメージの標準は distroless・非 root です。停止猶予は 30 秒で、アプリの既定 15 秒より長く設定します

## 実験的なログイン

既定ファイルに `accounts` はありません。有効化、プリセット、Cookie、種目ごとのログイン条件は[アカウント](账户登录与游玩准入.md)にあります。設定不備では起動を拒否し、無効なログイン方法は表示しません

腕試しとランキングは画面コンポーネントのみで、採点 API や有効化の設定は未実装です。`scoredChallenges`、`leaderboards` など未対応の項目を追加しないでください
