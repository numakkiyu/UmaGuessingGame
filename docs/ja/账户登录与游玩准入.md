# ログインと参加条件

ログインは実験的な機能で、既定では無効、現時点では有効化を推奨しません。設定後は第三者アカウントでログインでき、フレンド、パーティー、ランダム対戦ごとに必須設定ができます。通常の一人用はログイン不要です

## 本人性の扱い

外部の `(issuer, client_id, subject)` を内部 UUID に一意に対応させます。OIDC は検証済み `sub`、ネイティブ OAuth は現在のユーザー API の固定 ID を使います。異なるプラットフォームのアカウントを自動統合せず、名前、メール、IP、ブラウザー指紋で同一扱いにしません

アカウント UUID、匿名セッション ID、ルーム内六桁番号は別です。名前とアイコンはゲームの共通設定を使い、第三者の表示名で上書きしません

ログイン・ログアウト前に待機を取り消し、現在のルームから退出し、進行役を移して旧接続の権限を失効します。進行中の個人対戦はリタイア、チームメンバーの退出だけでは全体のリタイアにしません。処理に失敗した場合は元の身分を維持します

ログイン必須のルームでは同一アカウントの二席占有や重複待機を禁止します。匿名可の入口では従来の匿名ルールを使います

## 有効化

HTTPS ドメイン、固定コールバック、信頼するプロキシ、提供元のクライアント ID と秘密鍵、discovery・公開鍵・トークン API への接続が必要です

既存の設定をコピーし、ルートに `accounts` を追加します。ローカル設定は Git 対象外で、既存の種目と容量設定は維持します

```sh
cp config/cloud.json config/accounts.local.json
```

```json
{
  "accounts": {
    "enabled": true,
    "publicUrl": "https://game.example.com",
    "requireLogin": {
      "friend": false,
      "event": false,
      "matchmaking": false
    },
    "idleSeconds": 86400,
    "absoluteSeconds": 604800,
    "providers": [
      {
        "id": "microsoft",
        "enabled": true,
        "protocol": "oidc",
        "issuer": "https://login.microsoftonline.com/YOUR_TENANT_ID/v2.0",
        "clientId": "MICROSOFT_CLIENT_ID",
        "clientSecretEnv": "UMA_MICROSOFT_CLIENT_SECRET"
      },
      {
        "id": "google",
        "enabled": true,
        "protocol": "oidc",
        "issuer": "https://accounts.google.com",
        "clientId": "GOOGLE_CLIENT_ID",
        "clientSecretEnv": "UMA_GOOGLE_CLIENT_SECRET"
      }
    ]
  }
}
```

ドメイン、テナント、クライアント ID を置き換えます。`publicUrl` はパス・クエリ・ユーザー情報のない HTTPS Origin です。リクエストの Host からコールバックを組み立てません

秘密鍵は `clientSecretEnv` の環境変数に入れ、JSON、フロントエンド、Git、ログには保存しません。プロセスの秘密変数を用意して起動します

```sh
UMA_SECURE_COOKIES=true \
UMA_ALLOWED_ORIGINS=https://game.example.com \
UMA_ALLOW_MISSING_ORIGIN=false \
UMA_PUBLIC_ORIGIN=https://game.example.com \
go run ./cmd/server --config config/accounts.local.json --addr 127.0.0.1:8080
```

HTTP バックエンドの前に HTTPS リバースプロキシを置きます。Secure Cookie、Origin、信頼するプロキシは[設定リファレンス](配置参考.md)にあります

| 設定 | 動作 |
| --- | --- |
| accounts 省略、または enabled: false | 入口を非表示、従来の匿名参加 |
| enabled: true、三条件とも false | 任意ログイン、匿名参加も可能 |
| requireLogin.friend | フレンドにログイン必須 |
| requireLogin.event | パーティー作成・参加に必須 |
| requireLogin.matchmaking | 待機・確認・対戦に必須 |

三条件は独立です。全体を無効にして必須にした場合、秘密鍵不足、discovery 失敗では起動を拒否します。ログインを有効にしても無効な種目は開放しません

### Docker と無効化

Compose はアカウントの秘密変数を既定では渡しません。ローカル上書きファイルで明示します

```yaml
services:
  app:
    environment:
      UMA_CONFIG: /etc/umaguess/accounts.local.json
      UMA_PUBLIC_ORIGIN: https://game.example.com
      UMA_ALLOWED_ORIGINS: https://game.example.com
      UMA_ALLOW_MISSING_ORIGIN: "false"
      UMA_SECURE_COOKIES: "true"
      UMA_GOOGLE_CLIENT_SECRET: "${UMA_GOOGLE_CLIENT_SECRET:?set in deployment environment}"
      UMA_MICROSOFT_CLIENT_SECRET: "${UMA_MICROSOFT_CLIENT_SECRET:?set in deployment environment}"
```

```sh
docker compose --env-file /absolute/private/accounts.env \
  -f docker-compose.yml -f /absolute/private/compose.accounts.local.yml config --quiet
docker compose --env-file /absolute/private/accounts.env \
  -f docker-compose.yml -f /absolute/private/compose.accounts.local.yml up -d --build
```

設定ディレクトリは読み取り専用でマウント済みです。秘密の環境ファイルはデプロイ先だけに置きます。変更後に再起動し、無効化は `accounts` を削除するか `enabled` と三つの `requireLogin` を false にして再作成します。保存済みのアカウント対応は削除しません

## プリセット

| 提供元 | 接続方式 |
| --- | --- |
| Google | OIDC、issuer は https://accounts.google.com |
| Microsoft | 指定テナントの v2 OIDC。common は未対応 |
| GitHub | OAuth 2.0、/user の数値 id。OIDC 代理も利用可能 |
| X | OAuth 2.0 + PKCE、/2/users/me の data.id、users.read tweet.read |
| QQ・Facebook | 対応するログインを持つ OIDC 認証サービス経由 |
| その他 | 標準 OIDC、表示名とアイコンを設定可能 |

コールバックは `publicUrl + /api/v1/account/callback/{id}`。提供元へ完全一致の URL を登録します

## 共通の表示

有効なプリセットだけを配列順に表示します。一つは一列、二つ・四つは二列、その他は PC 最大三列、スマートフォン最大二列です

独自 OIDC の例

```json
{
  "id": "club",
  "enabled": true,
  "protocol": "oidc",
  "issuer": "https://identity.example.com",
  "clientId": "CLUB_CLIENT_ID",
  "clientSecretEnv": "UMA_CLUB_CLIENT_SECRET",
  "displayNames": {
    "zh-Hans": "同好会账户",
    "zh-Hant": "同好會帳號",
    "ja": "サークルアカウント"
  },
  "iconPath": "/assets/ui/providers/club.svg"
}
```

ID は英小文字で始まる小文字・数字・ハイフン 1–32 文字、最大 12 提供元です。独自名は三言語それぞれ 1–48 文字で、制御文字や方向制御文字を拒否します

`iconPath` は `/assets/ui/providers/` の SVG、PNG、WebP に限定します。`web/public/assets/ui/providers/` に置いてビルドし、外部 URL、data URL、パス移動は許可しません。読み込めない場合は共通アイコンを使います

右上の挨拶は有効時に未ログイン／ログイン済みへ切り替わります。設定パネルにボタンを表示し、失敗は既存の赤橙色ダイアログで案内します。待機中は重複クリックを抑止し、動きを減らす設定に従います

## API

| メソッド・パス | 用途 |
| --- | --- |
| GET /api/v1/config | 公開するログイン方法と参加条件 |
| GET /api/v1/account | authenticated、ログイン時の UUID、期限、メモリー内 CSRF |
| POST /api/v1/account/logins/{providerId} | returnTo を送り認証 URL を取得 |
| GET /api/v1/account/callback/{providerId} | 一回限りの処理を消費し 303 で戻る |
| POST /api/v1/account/renew | セッション延長と Cookie 更新 |
| DELETE /api/v1/account/session | 本サイトのログインを失効、204 |

`returnTo` は `/`、`/friends`、`/party`、`/matchmaking` のみ。延長とログアウトは Cookie、Origin、`X-Account-CSRF` が必要です。匿名プレイ用の CSRF と交換できません

## セッションと安全性

- 認可コードフローと S256 PKCE を使います。state はブラウザーと提供元に結び付き、五分間有効で一回限りです。OIDC は署名、issuer、audience、nonce、有効期限、認可先、存在する場合のアクセストークンハッシュを検証します。署名アルゴリズムは RS256／ES256 に限定します
- 上流の access token と ID token は該当するサーバーリクエスト内だけで扱い、DB に保存せずフロントエンドにも返しません。オフライン更新権限も要求しません
- Cookie は `__Host-uma_account`、Secure、HttpOnly、SameSite=Lax、Path=/ で、Domain を指定しません。DB にはランダム Cookie の SHA-256 ハッシュだけを保存します
- アイドル期限の既定は 24 時間、絶対期限は 7 日です。アイドル期限は 5 分から 7 日、絶対期限はアイドル期限以上で最大 30 日です。すべての延長に絶対期限を適用します
- ページの表示中に残り期限に応じて延長し、非表示時は継続しません。30 分経過後の延長で Cookie を更新し、旧値は送信済みの並行リクエスト用に 30 秒保持します。条件付き更新により、古い値への上書きを防ぎます
- CSRF はフロントエンドのメモリーだけで保持し、localStorage、sessionStorage、クエリー、キャッシュに保存しません。サーバー再起動後はアカウント状態を読み直して新しい値を取得できます
- 外部通信は信頼する設定の公開 HTTPS・443 番に限定します。私設・ループバック・クラウドメタデータのアドレス、URL のユーザー情報、リダイレクトを拒否し、接続数・時間・応答サイズを制限します
- 認証処理は最大 1024 件。ログインとコールバックは IP ごとに毎分 30 回、バースト 10 回を共有し、サイト全体の制限も適用します
- アカウント応答はキャッシュせず、コールバックには no-referrer を使います。認可コード、state、token、完全な Cookie、上流のエラーをアプリのログに含めません。プロキシでもコールバックのクエリーを記録対象から外します

ログアウトは本サイトのセッションを失効させます。第三者サイトのログイン状態は独立しています。現行構成は単一 SQLite とプロセス内認証トランザクションです。再起動後は未完了の認証をやり直します。複数インスタンスには共有保存先と統一した処理の実装が必要です

## 腕試しとランキング beta

レスポンシブな画面コンポーネントはありますが、採点・ランキング API は未接続です。公開入口や有効化の設定はありません。採点案では一人用キャラクター当てを対象とし、問題・正解・残り回数・期限・成績をサーバーで確定します。ブラウザーの記録はランキングに取り込みません

採点案の候補は、最大 8 回の誤答、1 局 20 分です。正式なルールと集計期間は採点 API の実装時に確定します

予定パスは `/api/v1/scored-challenges`、`/api/v1/leaderboards/{boardId}/entries`、`/me` です。ルートと OpenAPI にはまだ登録していません。[API](API与实时通信.md)に続きます
