# 画面と操作

明るい学園をイメージした画面に、問題と操作を見つけやすい情報構成を組み合わせます。公式サイトや BWIKI の配色を参考にしつつ、本ゲームの操作に合わせて設計します

## 情報の優先順位

現在の課題と主な操作を先に表示し、進行状況、補足、細かなルールを続けます。回答待ち、送信済み、一時停止、正解発表、結果は文字でも区別します。同じエラーをダイアログと常設の警告で二重に表示しません

## 画面サイズ

| 画面 | 構成 | 確認する点 |
| --- | --- | --- |
| スマートフォン縦向き | 一列のカード、短い操作単位、押しやすいボタン | ソフトキーボードがボタンを覆わず、長い名前が折り返され、ホバーなしで操作できる |
| 横向き・高さの低い画面 | 小さめのヘッダー、必要に応じた二列表示 | 主な操作が画面の高さに収まる |
| タブレット | 比較用の表、またはメインと補助欄 | タッチ領域が十分にあり、表が読める |
| PC | 情報比較は表、回答と補足は領域を分離 | 回答欄と補足情報が重ならない |
| 大画面 | 読み取り専用の進行表示、遠くから読める文字 | 遠くから読め、非公開の答えや操作を表示しない |

表をカードに変えても、項目の意味、順序、状態、操作を保ちます。二次元比較に必要な部分だけ横スクロールを使います。長い訳語や名前は折り返し、固定ボタンには余白とセーフエリアを確保します。視覚上とキーボードの移動順を一致させます

## コンポーネント

ボタン、セレクター、ダイアログ、入力エラーは共通コンポーネントを使います。ゲーム内の確認に `alert`、`confirm`、`prompt` は使用しません。ブラウザーの権限画面は置き換えず、必要な操作をユーザーが開始します

ダイアログを開いたら内部へフォーカスを移し、閉じたら元のボタンへ戻します。Escape、キャンセル、背景の操作制限を揃え、Portal の配置と重なり順を管理します

## 色と動き

`web/src/styles/tokens.css` で色、余白、文字サイズ、動きを管理します。判定は色だけでなく文字や記号でも伝え、背景と合成した実際のコントラストを確認します。装飾画像は読み上げ対象から外します

選択、裏返し、結果、順位の変化を短い動きで示します。変形と不透明度を優先し、毎フレームのレイアウト変更を避けます。動きを減らす設定では終状態をすぐ示し、時間切れや判定をアニメーション終了に依存させません

画像の取得に失敗しても領域を維持し、背景装飾が問題や主な操作を覆わないようにします

## 書体とウェイト

本文、操作部、数字、見出しに源ノ角ゴシックの地域別字形を使います。本文は 400、見出しと操作部は 600 とし、サイズと余白で階層を表します。コードは等幅書体です
