# コントリビューション

不具合の修正、問題データや訳名の訂正、操作や文書の改善を歓迎します。大きなルール変更やデータモデルの変更は、Issue で現状の問題と変更後の動作を共有してください

## 開発を始める

[クイックスタート](快速开始.md)で環境と起動方法を説明しています。アプリと独立ツールの依存は `make web-install` でインストールします。文書は `pnpm --dir docs install --frozen-lockfile` を使用します

## 変更に合わせて更新するもの

| 対象 | 関連箇所 |
| --- | --- |
| API | OpenAPI、生成型、HTTP 実装、呼び出し元、契約テスト |
| リアルタイム通知 | スキーマ、閲覧権限、復元と再送 |
| ルール | 不正入力、段階、時間切れ、採点、公開・非公開データ |
| 問題データ | 出典、確度、修正内容、素材と内容確認の記録 |
| UI | 三言語、キーボード、狭い画面、大画面表示、動きを減らす設定 |
| 設定 | 既定値、優先順位、コンテナーへ渡す変数、公開例 |

ルールは `internal/modes` に置き、HTTP・SQL・ブラウザーに依存させません。身元と権限はサーバーのセッションとメンバー関係で判断します。乱数、並び順、採点単位を制御し、再送で二重加点や時間延長が起きないようにします

身元・チーム・進行役の権限はサーバーの記録で判断し、リクエスト内の役割を信用しません。答えは閲覧権限と段階に応じて配信します。画面上で隠すだけでは保護になりません。問題データの変更では出典・分類・確認記録・利用条件のレポートも更新します

## Git に含めるファイル

ソース、テスト、依存ファイル、ロック、Docker、CI、Make、公開設定、出典のある問題資料と必要素材を管理します

実行 DB、秘密鍵、バックアップ、ローカル設定、ログ、生成ページ、バイナリー、コンテンツパック、依存ディレクトリー、取得キャッシュ、一時作業ファイルは含めません。`internal/spafs/dist/.gitkeep` だけは未ビルド時の埋め込みディレクトリーを維持するために残します

40 kbps VBR、Opus / WebM 音声は `data/assets/audio/library/` に保存し、`data/assets/audio/manifest.json` に出典・ファイルの SHA-256・サイズ・長さを記録します。問題への採用には `data/manual/audio-clips.review.json` の話者・台詞・名前の漏洩・試聴の確認が必要です。使用する画像も出典を残し、ダウンロードのキャッシュはコミット対象から除外します。単一ファイルは 50 MiB 以下とします

`pnpm run repo:check` は Git インデックスから対象外ファイル、音声記録、サイズを調べます。文書やテストはクリーンな clone で使用できる状態にします

## Pull Request

一つの問題に絞り、発生条件、変更後の動作、実行した開発コマンドと結果、未対応部分を記載します。UI の変更は主要サイズの画像を添付し、モバイルでも同じ情報を扱えることを説明してください

## 継続的インテグレーション

`.github/workflows/ci.yml` はプッシュとプルリクエストで次のチェックを実行します

| 対象 | 内容 |
| --- | --- |
| リポジトリ | Git インデックス、サイズ、出典、音声形式、ワークフロー構文 |
| フロントエンド | 型、コード規約、三言語の文言、API 参照、テスト、ビルド、配信サイズ |
| サーバー | 整形、静的解析、競合検出、カバレッジ、既知の脆弱性 |
| 問題と音声 | 全 WebM のデコード、リスト照合、問題ビルド、実データでの採点 |
| ドキュメント | 三言語ページ、リンク、VitePress ビルド |
| API とイメージ | OpenAPI 型の同期、ルートの整合性、コンテナビルド |

カバレッジレポートは7日間保存します。`pages.yml` が文書サイトを公開し、プルリクエストの文書ビルドは CI が担当します
