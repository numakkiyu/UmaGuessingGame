# クイックスタート

ソースを取得し、PC またはサーバーでゲームを動かします。コマンドはリポジトリのルートで実行します

## 環境

- Go 1.26.11 または互換性のある新しいバージョン
- Node.js 24、pnpm 10.33.0：フロントエンドのビルド用
- GNU Make。Windows は WSL2 を利用可能
- Docker Compose v2 は任意

## 初回起動

```bash
make web-install
make web-build
make embed-spa
make embed-spa-check
make content-compile
make content-verify
make dev
```

`http://localhost:8080` を開きます。停止は端末で Ctrl+C。`make dev` は `:8080` で待ち受け、`.cache/runtime` にデータを保存します

`.cache/runtime` は開発用の保存先です。長期保存するデータには永続ディレクトリーと定期バックアップを用意してください

`make web-install` はアプリと `web/tools/toolchain/` の依存関係をそれぞれインストールします。`go run ./cmd/server` を直接実行する場合の既定値は `127.0.0.1:8080` と `data/runtime` です

### Make を使わない場合

```bash
pnpm --dir web install --frozen-lockfile
pnpm --dir web/tools/toolchain install --frozen-lockfile
pnpm --dir web run build
```

Go の配信先にビルド済みページを置き、問題データを準備します

```bash
go run ./cmd/content build --root . --out content
go run ./cmd/content verify --out content
go run ./cmd/server --web web/dist --content content
```

フロントエンドを配布用ディレクトリーにコピーする場合は、旧ファイルが残らないようディレクトリー全体を置き換えます

## フロントエンドを変更する

バックエンドを起動した状態で、別の端末から実行します

```bash
pnpm --dir web run dev
```

端末に表示された Vite の URL を開きます。既定のポートは 5173、API の転送先は `http://127.0.0.1:8080`。転送先は `UMAGUESS_API_TARGET` で変更できます。Origin を制限している場合は開発用 URL も登録します

Go が配信する画面を更新するときは `make web-build` と `make embed-spa` を実行し、Go を再起動します

## スマートフォンから接続する

同じネットワークに接続し、IP を PC の LAN アドレスに置き換えます

```bash
UMA_ADDR=0.0.0.0:8080 \
UMA_PUBLIC_ORIGIN=http://192.168.1.20:8080 \
UMA_ALLOWED_ORIGINS=http://192.168.1.20:8080 \
make dev
```

スマートフォンで `http://192.168.1.20:8080` を開き、ファイアウォールでポートを許可します。HTTP の LAN 接続ではオフラインキャッシュに安全なコンテキストの制約があります

## Docker

```bash
make content-compile
make content-verify
cp .env.example .env
docker compose up -d --build
```

`.env` は Compose の変数展開用です。Go は自動では読み込みません。公開 URL を変える場合は `UMA_PUBLIC_ORIGIN` と `UMA_ALLOWED_ORIGINS` の両方を設定します

問題データは読み取り専用、実行データとバックアップは別のボリュームに保存します。`docker compose down` では保持されますが、ボリューム削除はデータを失います
